# dify/kb — KB 用ダミー文書の投入状態台帳（④ダミーデータ）

`dify/kb/<管理番号>/` は、実機（Dify Cloud）の Knowledge（KB）に投入するダミー文書の正本です。
このファイルは**設計側の意図**（どの管理番号の文書を、どのタイミングで実機へ投入する想定か）を書く場所です。
**実機に実際に投入済みかどうかの事実の正本は `dify/state/<env>.yml`（Issue #121 W2、現時点では未生成）・
`dify/results/**`（実行結果）であり、このファイルではありません**（`CLAUDE.md` §7「設計値と実機の事実をファイルで分ける」）。

## 増量分（Issue #205 PR-5）の投入について

`scripts/dify/kb_upload.py`（フラグ無し）は同名文書をスキップして新規だけ追加するため、今回の増量
（KN-01・KN-02・KN-03・GN-01 に各 3 本ずつ）は既存文書を書き換えない・消さない。したがって
`K1〜K8`（`dify/DEPLOY.md`）の削除系の歯止めには一切当たらない。

投入・回帰の手順は Issue #205 本文および `docs/handoff/2026-09-09-demo-assets.md` §12 の後続 Issue 案を参照。
概略：

1. `dify-ops.yml` を `workflow_dispatch`。`op: kb_upload` / `codes: KN-01 KN-02 KN-03 GN-01`
2. `op: run_tests` / `codes: KN-01 KN-02 KN-03 GN-01`（4 本 × 4 ケース＝16 件の回帰）
3. FAIL したら**期待語（`dify/tests/*.json` の `expect` / `expect_not`）は緩めず、追加した KB 文書のほうを直す**
   （表現を薄める・`edge` 寄りの記述を削る）。それでも直らなければその追加文書を取り下げる

## 金融（KN-06・KN-08）について

金融には投入先の Dify アプリがまだ 1 本も無い（W4 未着手）。したがって KN-06・KN-08 の文書は
①モックのデモ（`catalog.html`）で使う素材、②W4 実装時にそのまま KB へ移せる素材、という位置づけで、
**実機投入は行わない**。`docs/service-map.md` の DSL 列が `—` のままなので「KB 素材はあるが実機未実装」と
正しく読める。
