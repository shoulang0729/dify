# data/world — 架空世界マスタ

台本（`mock/js/data/scenarios/**`）・KB 用ダミー文書（`dify/kb/**`）・テスト入力（`dify/tests/**`）・
ユースケース文書（`docs/dify/usecases/*.md`）に共通して登場する、架空の会社・人・品番・設備・数字の**正本**。

出典：`docs/handoff/2026-09-07-repo-layout-v2.md` §2（設計）。Issue #84 PR-1 で新設。
金融（在中日系銀行）の第 2 世界は `docs/handoff/2026-09-08-finance-catalog.md`（Issue #120 PR-2）で追加。
IT（在中日系 SIer）の第 3 世界は `docs/handoff/2026-09-11-it-industry.md`（PR-1）で追加。

**この会社・人物・数値はすべて架空です。実在の企業・製品とは関係ありません。**

## 3 つの世界（製造業／金融／IT）

- **製造業**：`data/world/mfg/`（下表）。青嶺精工／蘇州工場の世界
- **金融**：`data/world/fin/`（下表）。碧洋銀行／上海本部の世界
- **IT**：`data/world/it/`（下表）。翠雲システムズ／上海拠点の世界。**顧客が青嶺精工（mfg）と碧洋銀行（fin）という関係になる唯一の世界**
- **世界の語彙は混ぜない。ただし IT 世界だけ、社名と拠点名に限って例外を認める**：IT の台本・KB・テストは `data/world/it/` にある値だけを使うのが原則だが、`clients.csv` の `ref_world` 列で参照を明示したうえで、**青嶺精工・碧洋銀行の社名と拠点名（蘇州工場・上海本部）だけ**参照してよい。**人・部署・品番・設備・KPI・文書番号は跨がない。** 逆方向（`mfg`/`fin` の台本・KB・テストに IT 世界の語を出すこと）は禁止。製造業・金融の間はこれまでどおり語彙を混ぜない（青嶺精工・K 社・PX-200 などを金融側で使わない。逆も同様）。詳細は `data/world/it/company.md`「顧客と世界の跨ぎ」・設計書 `docs/handoff/2026-09-11-it-industry.md` §3-4
- 製造業側は初版（Issue #84 PR-1）でこのディレクトリ直下に置かれていたが、Issue #120 PR-2 で `data/world/mfg/` へ移動した（`git mv`。内容は不変）。**参照するときは新しいパス `data/world/mfg/*` を使うこと**

## 重要な原則（load-bearing。`docs/handoff/2026-09-07-repo-layout-v2.md` §2-1）

**`data/world/` は正本だが、自動反映はしない。** モックのデータ層も KB 文書も、マスタから生成しない
（台本は文脈で表現が変わる：目標値・前月値・当月値）。`tools/check-world.mjs` は**報告するだけ**（FAIL にしない）。

## 追加時のルール

1. **新しい人名・社名・品番・設備・数字を出すときは、まず `data/world/` に足す。** 台本・KB 文書・テストはマスタにある値だけを使う
2. 既にある値を**別の文脈で違う数字にしたい**とき（改善事例など）は、`kpi.csv` に行を足して `note` で文脈を書く。台本側に裸の新しい数字を書かない
3. **取引先に社名を付けない**（PM 決定 PT-8）。記号（`K 社`）と役割名だけ。空白は `K 社`（半角スペース）に揃える — 既存の `K社` 8 か所は本 PR では**直さない**（`mock/**` 不可侵）。`tools/check-world.mjs` が warn として出し続ける
4. 実在の企業名・型番・URL・人名を混ぜない（`docs/dify/implementation-guide.md` §5-3）
5. 個人情報の見本（身分証 18 桁・電話 11 桁）は**架空値**を `people.csv` に持たず、テスト側（`dify/tests`）にだけ置く
6. **3 つの世界を通じて姓名の完全一致を作らない。** 名（下の名前）の 3 回目以降の再利用も避ける（デモの口頭説明で「建国さん」が 3 人になると事故る）。**取引先・協力会社の記号は世界ごとに体系を分ける**：`mfg` はラテン大文字（`K 社`）、`fin` は十干（`甲社`）、`it` はギリシャ文字（`α 社`）

### W8（KPI）が拾える範囲と拾えない範囲（重要）

W8 は 2026-09-10 までに**表記の書き換えで 2 回すり抜けられた**（簡体字への書き換え・括弧で隣接を
崩す）。その 2 件を含む 3 パターンは強化（上記 PR）で拾えるようになったが、**さらに reviewer が独立に
試したところ、強化後もなお次の 6 パターンは拾えない**ことを一時ファイルでの実測で確認した（実装は
このまま変えていない。塞がない理由は後述）。詳細な実装は `tools/check-world.mjs` の
`buildKpiValueRegex` 付近のコメントを参照。

**拾う**：
- `kpi.csv` の全行（`name_ja`/`name_zh`。数語だけのハードコードではない）のラベルと登録値
  （`target`/`current`/`prev`）の突き合わせ
- ラベルの表記ゆれ（働／動／动）
- ラベルと数値の間、最大 6 文字までの隣接の崩し（括弧・助詞「は/の/が」・コロン・読点など。
  この 6 文字の中に実際の改行文字が入っている場合も含む）

**拾わない**（reviewer 実測。6 パターン）：
1. 全角数字＋全角％（例: `稼働率８６．０％`）
2. 改行を挟む（例: `稼働率\n86.0%`）——ただし挟まるのが本物の改行文字なら上記のとおり拾える。
   拾えないのは `dify/tests/**.json` のように**生テキストとして読み JSON.parse しない**対象で、
   改行がエスケープ表現（バックスラッシュ＋`n` の 2 文字）のまま残っているケースに限る
3. 小数表記（例: `稼働率 0.86`）
4. 「パーセント」表記（例: `稼働率 86 パーセント`）
5. ラベルの言い換え（例: `設備の稼働は 86.0%`）
6. 隣接 7 文字以上、上限超え（例: `稼働率-------86.0%`）

**なぜ全部塞がないか**：`check-world.mjs` は **warn のみで CI に入れない道具**。誤検知（無関係な数字を
拾ってしまうこと）を増やすと、この「未統一」台帳自体の価値が落ちる。上記 6 つを塞がないのは
**設計判断であって、やり残しではない**。

**⚠️ いちばん大事なこと**：**W8（延いては `check-world.mjs` 全体）を通ることは、`CLAUDE.md` §2-13
「架空データの正本は `data/world/`」を守っている証明にはならない。** 新しい数値を書くときの本来の
手順は `data/world/` を見て書くことであり、この検査は取りこぼしを拾うための保険にすぎない。
