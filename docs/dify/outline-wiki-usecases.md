# Outline Wiki 前提のユースケース案

PM の予定「Outline で社内 Wiki を作る」を前提に、(1) Outline の事実整理、(2) 既存 41 サービスへの影響、(3) Outline があるからこそ成立する新規ユースケース案（`OW-xx`。**管理番号は付けない**）、(4) PM 判断待ち、をまとめる。
連携の実装は `platform-components.md` **PC-05**。architect 成果物。モック・`docs/handoff/**` には触れていない。

## 3. 新規ユースケース案（OW-01〜OW-10）

成熟度案は既存の基準（提供中＝標準機能で動く／試行版＝データ整備・連携が要る／構想＝運用・判断が先）で仮置き。**既存サービスと重なるものは統合を第一候補**にし、管理番号を増やさない。

### OW-01 会議録 → Wiki ページ化

| 項目 | 内容 |
|---|---|
| 狙い | 議事録を Outline に**下書き**で置き、決定事項・宿題をページに残す。次回はそのページを入力にして論点を引き継ぐ |
| インプット | 録音／メモ（DC-02 と同じ）、前回議事録ページ（`documents.info`） |
| Dify 構成の要点 | DC-02 の Workflow 末尾に `http-request`（`documents.create`、`publish: false`、`collectionId`＝会議体のコレクション）。見出しは議事録テンプレート（`documents.templatize`）に合わせる |
| Outline 側で必要なもの | 会議体ごとのコレクション、議事録テンプレート、公開担当 |
| 成熟度案 | 提供中 |
| 既存との重なり | **DC-02 に統合**（§9「書く」）。新サービスにしない |

### OW-02 Wiki 更新差分の担当者通知

| 項目 | 内容 |
|---|---|
| 狙い | 規程・手順ページが公開されたら、影響する分類の担当者に **③ `notify`** を出す（モックの EN-01／KN-05 の `notify` と同じ見え方） |
| インプット | Outline Webhook `documents.publish`／`documents.update`（`Outline-Signature` 検証） |
| Dify 構成の要点 | Webhook Trigger → `documents.export` で新旧版を取得 → PC-12 `diff-core`（Workflow as Tool）→ 影響索引で宛先分類を決定 → PC-01 に `notify` を POST → PC-14 で通知 |
| Outline 側で必要なもの | Webhook 購読、コレクション → 分類（`mine`）のマッピング表 |
| 成熟度案 | 試行版 |
| 既存との重なり | EN-01（取引先仕様）・KN-05（当局通達）は**外部**文書の差分。OW-02 は**社内 Wiki** の差分で入口が違う。PC-12 を共用し、**新規候補**（KN 系） |
