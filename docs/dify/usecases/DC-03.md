## 1. 業務シナリオ
- **トリガー**：担当者が能動的に開く（新人配属・異動・作業標準書の改版のたび）。③業務フィードでは作業標準書の改版を `notify` として受けると資料の更新が要ることに気づける（第 2 段階）
- **登場人物**：作成者＝教育担当（生産技術）、確認者＝ライン監督者（日本人駐在員）と安全衛生委員、受け手＝新人・異動者（母語 zh）
- **いまの手順（Before）**
  1. 日本語の作業標準書（最新版 Rev.D）を読み、教える順番を考える（半日）
  2. 過去の不具合台帳（17 件）から新人向けの事例を選び、写真を探す（半日）
  3. 中国語スライド・確認テスト・OJT チェックリストを作る（2 日）。日本語の指導ポイントは監督者が別に口頭で伝える
  4. 改版のたびに全部を手直しするため、資料が古いまま使われがち
- **エージェント導入後の手順（After）**
  1. 【入力】作業標準書・不具合事例・安全ルールをアップロード（Outline にあればコレクションを指定）
  2. 【生成】中国語のスライド構成案・確認テスト（正答と根拠付き）・OJT チェックリスト・監督者向け日本語指導ポイントが返る
  3. 【確認】教育担当が事例の選定理由と設問の正答を確認。設問の難易度・枚数を対話で調整
  4. 【決める】監督者が指導ポイントと合格基準（正答率）を決める。写真・図の準備は人（AI は「準備リスト」を出す）
  5. 【保存】Outline「教育資料 › ライン別」にドラフト保存 → 監督者承認後に確定。pptx/docx 化は `PC-13`
- **成功の定義**：資料作成 3 日 → 半日。作業標準書の改版から教育資料の更新まで 1 週間以内。確認テストの設問に必ず根拠（標準書の項番・不具合番号）が付く

## 3. 観点（LLM に守らせる業務ルール）
- 手順・数値（Vc 20／f 0.06／クーラント圧 2.0 MPa 等）は**作業標準書の記載どおり**。標準書に無い数値・手順を教材に書かない。補足したい一般知識は「※標準書外の補足」と明示
- 確認テストの各問に**根拠（標準書の項番 or 不具合番号）**を必ず付ける。根拠が付けられない設問は作らない
- 不具合事例の選定基準を明示（新人が起こしやすい／安全に直結／直近）。選外の事例も件数と理由を 1 行で
- 安全に関する記述は安全ルール文書の文言を優先。安全ルールと標準書が矛盾したら**両方を引いて「要確認」**（AI が裁定しない）
- 中国語は現場の作業者向け（短文・命令形・専門用語は用語集の呼称）。日本語の指導ポイントは監督者向け（理由・背景を含む）
- 個人情報（`PC-10`）：不具合事例の**作業者名は教材に出さない**（番号・現象・原因のみ）。提案者・発見者を称える目的でも氏名は監督者版のみ、かつ本人同意を前提
- 不確実時の定型：「この設問の根拠を標準書から特定できませんでした。項番を指定するか設問を削除してください」／「无法从标准书确定该题依据，请指定条款号或删除该题」
- 出力形式：Markdown（4 セクション固定）＋ §5-3 JSON（スライド枚数・設問・チェック項目を `PC-13` が pptx/docx/xlsx に変換）

## 4. Dify 構成
- **アプリ種別**：**Workflow**（アップロード → 4 種の成果物を並列生成）
- **ノード列**
  1. `start`：`files`（file-list）、`line`, `audience`, `weeks`, `out_lang_main`（zh/ja）, `out_lang_sub`（ja/zh/none）, `question`（任意）
  2. `iteration`（files）→ `if-else`（形式）→ `document-extractor`（電子 PDF/docx/xlsx）／`tools/mineru`（スキャン PDF）→ `variable-aggregator`
  3. `llm`（選定）：不具合事例から新人向け 3 件を選定し JSON（選定理由・選外件数）
  4. 並列 `llm`×4：(a) スライド構成 12 枚（主言語） (b) 確認テスト 10 問（主言語、正答・根拠） (c) OJT チェックリスト（週次） (d) 監督者向け指導ポイント（副言語）
  5. `llm`（整合）：4 出力の用語・数値を標準書と突合し、不一致を `warnings` に
  6. `template-transform` → `end`
  - `question` がある場合（「Q3 と Q6 の全文と答え」「写真は何を用意」）は 4 の代わりに `llm`（QA）で前回 JSON と抽出文書から回答
- **Knowledge**：原則不要（アップロード文書のみで動く）。Outline の作業標準書を常時参照したい場合は KB `dc3-work-standards`（`PC-05` 同期、メタデータ `line`/`rev`/`lang`）を追加し、`rev` の最新だけを引く
- **プラグイン／ツール**：`tools/mineru`（スキャン PDF。自前デプロイなら越境なし）、`tools/dify_extractor`（KB 投入時）。`tools/slidespeak`（pptx 生成）は SaaS のため中国拠点では非推奨 → pptx は `PC-13`
- **モデル**：Qwen3-235B-A22B-Instruct（中国語教材の生成・日本語の読解）。選定・整合は Qwen3-32B でコスト削減可。日本語指導ポイントは監督者が読むため品質確認（`PC-08`）
- **参照 DSL**：`../templates/07-excel-document-extractor-echarts.yml`（file-list → document-extractor → LLM の骨子）、`../templates/08-mineru-pdf-parse-demo.yml`（MinerU の tool ノード）
- **入出力変数**

| 変数 | 型 | 必須 | 説明 |
|---|---|---|---|
| `files` | file-list（pdf/docx/xlsx） | ✓ | 標準書・不具合事例・安全ルール |
| `line` | string | ✓ | 対象ライン |
| `audience` | string | ✓ | 受講者（人数・属性） |
| `weeks` | number | ✓ | OJT 期間（週） |
| `out_lang_main` / `out_lang_sub` | select | ✓ / — | 主言語／副言語 |
| `question` | paragraph | — | 追加質問 |
| `materials_md` | string | 出力 | 4 セクション Markdown |
| `materials_json` | object | 出力 | §5-3 |
| `warnings` | array | 出力 | 標準書との不一致・根拠なし設問 |

## 5. プロンプト
### 5-1. System
```text
あなたは青嶺精工（蘇州）の教育担当を支援するアシスタントです。作業標準書・不具合事例・安全ルールから、新人・異動者向けの教育資料セットを作ります。
守るルール：
- 手順・数値・条件は作業標準書 {{context}} の記載どおりに書く。標準書に無い数値や手順を足さない。一般知識を補うときは「※標準書外の補足」と明示する。
- 確認テストの各問に「根拠：標準書 §x.y」または「根拠：NC-xxxx」を付ける。根拠が示せない設問は作らない。
- 不具合事例は {{audience}} に関係が深いものを 3 件選び、選定理由と選外件数を書く。作業者の氏名は書かない。
- 安全に関する記述は安全ルール文書を優先。標準書と矛盾する箇所は両方を引用し「要確認」と書く。裁定しない。
- 主言語 {{out_lang_main}}：作業者向け（短文・命令形・用語は {{glossary}} の呼称）。副言語 {{out_lang_sub}}：監督者向け指導ポイント（理由・背景を含む）。
- 追加質問 {{question}} には質問の言語で答える（日本語なら日本語、中国語なら中国語）。
- 特定できないときは「この設問の根拠を標準書から特定できませんでした」と書く。
出力：JSON（指定スキーマ）→ 区切り線 → Markdown（1 スライド構成／2 確認テスト／3 OJT チェックリスト／4 監督者向け指導ポイント）。
```
### 5-2. User テンプレート
```text
対象ライン：{{line}}／受講者：{{audience}}／OJT 期間：{{weeks}} 週
主言語：{{out_lang_main}}／副言語：{{out_lang_sub}}
用語対訳：{{glossary}}
--- 抽出文書（ファイル名の見出し付き。標準書は項番を保持） ---
{{context}}
--- 追加質問（無ければ空） ---
{{question}}
スライドは 10〜14 枚、確認テストは 10 問（4 択、正答率 80% で合格）、チェックリストは週ごとに 8〜12 項目、指導ポイントは 3〜5 件。
```

```json
{ "line": "L3", "lang_main": "zh", "lang_sub": "ja",
  "slides": [ { "no": 1, "title": "…", "bullets": ["…"], "source": "標準書 §1" } ],
  "quiz": [ { "no": 3, "q": "…", "choices": ["A…","B…","C…","D…"], "answer": "B", "evidence": "NC-2024-0118" } ],
  "ojt_checklist": [ { "week": 1, "items": [ { "no": 1, "text": "…", "sign": true } ] } ],
  "supervisor_points": [ { "no": 1, "text": "…", "why": "…", "evidence": "NC-2024-0118" } ],
  "case_selection": { "selected": ["NC-2024-0118","NC-2025-0203","NC-2025-0417"], "excluded_count": 14, "criteria": "…" },
```

### 5-4. Few-shot
不要。設問形式は System の指定（4 択・根拠必須）で固定できる。標準書の実文を few-shot に入れると改版時に古い数値が残る

## 6. 検証観点
| 観点 | 基準 | 測り方 |
|---|---|---|
| 正確性 | 教材中の数値・手順が標準書と一致 100% | 抽出した数値を Code で標準書テキストと突合＋人手 |
| 根拠 | 設問の根拠付与率 100%、根拠の実在 ≥ 95% | JSON 自動チェック＋人手抽出検査 |
| 網羅 | 標準書の主要工程（段取り・加工・検査・異常時）がスライドに存在 | チェックリスト |
| 言語 | 主言語・副言語が指定どおり、追加質問は入力言語 100% | 自動判定（`PC-07`） |
| 教育効果 | 監督者による資料の採用率（手直し 3 か所以内） | 月次アンケート |
| 速度 | p95 < 120 秒（並列 4 LLM、PDF 40 ページ） | Langfuse（`PC-09`） |
| 安全 | 作業者氏名の混入 0 | 負例セット |

- **評価方法**：リリース前に 2 ライン分の実文書（匿名化）で人手採点。運用後は監督者の手直し件数を記録

## 8. 別出しが必要なもの
- `PC-03`：スキャン PDF の OCR（自前 MinerU）。標準書の項番を保持する抽出設定
- `PC-13`：JSON → pptx（スライド）／docx（テスト・指導ポイント）／xlsx（チェックリスト、サイン欄付き）
- `PC-05`：Outline「作業標準書」の最新版参照と「教育資料」への保存
- `PC-06`：現場用語の対訳（治具・初品・切削液 …）。LG-02 と共有
- **無くても動く範囲**：アップロード → Markdown 4 セクションまで。OCR・pptx・Outline は段階導入

## 9. Outline Wiki との関係
- **読む**：「作業標準書 › ライン別」（最新 Rev のみ。旧版は `rev` メタデータで除外）、「安全衛生 › ルール」、「用語集」
- **書く**：「教育資料 › ライン別 › <標準書 Rev>（ドラフト）」に保存。監督者承認後に確定。標準書の改版時は旧教育資料に「要更新」タグを付ける運用（第 2 段階で `notify` と連動）
- 教育資料に写真を入れる作業は Outline 上で人が行う（`photo_requests` をチェックリストとして残す）
