## 1. 業務シナリオ
- **いつ起きるか（トリガー）**：年間契約更新・新規購買で複数社の見積が揃ったとき、担当者が能動的に開く。③業務フィードでは `due`（契約更新期限）
- **登場人物**：購買担当（入力・推奨案の起案）、購買課長（決定）、生産技術（工具寿命の実績提供）、外部：サプライヤー 3 社（見積の出し手）
- **いまの手順（Before）**：PDF・Excel・メール本文の見積を Excel に手で転記（1 社 30 分）→ 通貨（USD/RMB）・単位（本／箱）・税込／税抜を揃える計算で間違いが出る → 前回価格を過去メールから探す → 値上げ理由（材料市況）の妥当性は感覚で判断 → 課長報告まで半日〜1 日
- **エージェント導入後の手順（After）**：
  1. 担当者が見積ファイル（PDF・xlsx・txt）を**複数選択でアップロード**し、比較条件（年間数量・基準通貨・税区分）を入力
  2. エージェントが各見積から単価・MOQ・納期・支払条件・通貨・単位・税区分を **JSON で抽出**（LLM）し、**Code ノードで**基準条件（RMB／本・税抜・年間数量）に正規化・年間総額・前回比を計算
  3. 前回発注価格（`PC-04`）と社内の値上げ妥当性ルール（KB）を引き、LLM が比較表・妥当性コメント・交渉ポイントを**計算結果を転記して**書く
  4. **人が決める場所**：推奨サプライヤーの選定・交渉方針・試用の可否は購買担当が起案し課長が決める。エージェントは「候補と根拠」まで
  5. 比較表を `PC-13` で xlsx 出力して報告
- **成功の定義**：3 社比較の所要時間 半日 → 30 分。単位・通貨の正規化ミス 0。値上げ交渉に数値根拠が毎回付く

- **入力言語の扱い**：日本語・中国語のどちらでも受け、**入力言語で返す**（`CLAUDE.md` §2-5）。見積書自体は英語でも読む。交渉文は宛先（サプライヤー）の言語を `target_lang` で指定
- **入力の欠け・曖昧さ**：年間数量が無いと総額比較ができない →「年間数量が未入力です。単価比較のみ出力します」。見積に通貨・税区分の記載が無いとき → 抽出 JSON の該当フィールドを `null` にし、表に「⚠ 記載なし・要確認」と出す（**推定しない**）

## 3. 観点（LLM に守らせる業務ルール）
- **正規化・総額・前回比・寿命換算・妥当性の計算は Code ノード**。LLM は抽出（文書→JSON）と説明（JSON→文章）だけ。抽出時も**記載どおりの値と単位**を写し、換算しない
- **値上げ妥当性は「社内ルール × 入力された市況」の計算結果を転記**する（例：材料構成比 30% × 市況 +18% = +5.4%）。構成比・市況値の出典（KB のメモ名／入力値）を明記。市況が入力されていなければ妥当性判定は「判定材料なし」
- **競合価格をサプライヤーに開示する文面では社名を出さない**（「他社 2 社の同規格見積は RMB 172〜178」）
- **未検証の性能値（カタログ寿命）は「未検証」を付す**。実績のあるものと並べる時は区別を明示
- **禁止**：見積に無い条件（納期・支払）を補う／推奨サプライヤーを断定する（「最安は」「推奨候補は」までに留め、決定は人）／社外秘の前回価格を交渉文に書く
- **不確実時の定型文**：「{{file}} から {{field}} を読み取れませんでした。原本を確認してください」
- **出力形式**：比較表（Markdown、列＝サプライヤー、行＝項目）＋妥当性コメント＋交渉ポイント。後工程用に §5-3 の JSON

## 4. Dify 構成
- **アプリ種別**：**Workflow**（ファイル一括投入→表）。台本の Q1「交渉文」Q2「試用の買い方」は同じ抽出 JSON を会話変数に持つ **Chatflow** 版で対応（第 2 段階）
- **ノード列**：
  1. Start（`quotes` file-list 必須／`annual_qty` number／`base_currency` select（RMB/USD/JPY）／`tax_basis` select（税抜/税込）／`fx` number／`market_note` paragraph 任意／`target_lang` select）
  2. Iteration（`quotes` 各ファイル）：If/Else（拡張子）→ Document Extractor（pdf 電子・xlsx・txt）／`tools/mineru`（スキャン PDF）→ LLM（`extract`：§5-3 の `quote_item` JSON、記載どおり）
  3. HTTP Request（`PC-04`）：前回発注価格・実績寿命（無ければスキップ）
  4. Knowledge Retrieval（KB `nm-purchase-rules`：材料構成比メモ・値上げ妥当性ルール・購買規程）
  5. **Code（Python）`normalize`**：通貨換算・箱→本・税抜化・年間総額・前回比・寿命換算コスト・妥当性上限（構成比×市況）を計算。抽出漏れは `null` のまま `warnings` に積む
  6. LLM（`compose`）：比較表・妥当性コメント・交渉ポイント（§5）
  7. `tools/microsoft_excel_365` または Code で CSV/xlsx → `PC-13`
  8. End（`comparison` JSON／`report` markdown／`warnings`）
- **Knowledge**：`nm-purchase-rules`（Outline 同期：購買規程・材料構成比メモ・値上げ判断基準、`PC-05`）。前回価格は KB でなく API（表の結合が要る）
- **プラグイン／ツール**：Document Extractor（本体）／`tools/mineru`／`tools/dify_extractor`（KB 投入）／`tools/json_process`（抽出 JSON の整形。Code でも可）／`tools/microsoft_excel_365`（任意）
- **モデル**：既定 `models/siliconflow` Qwen3-235B-A22B-Instruct。`extract` は Qwen3-32B で十分（コスト）。代替 DeepSeek-V3.x／`models/ollama`（越境ゼロ）
- **参照 DSL**：`../templates/07-excel-document-extractor-echarts.yml`（file-list→Document Extractor→LLM の骨子）、`../templates/08-mineru-pdf-parse-demo.yml`（MinerU の tool ノードと iteration）
- **入出力変数**：`quotes` file-list 必須／`annual_qty` number 任意／`base_currency` select 必須／`tax_basis` select 必須／`fx` number 任意（無ければ `PC-04`）／`market_note` string 任意／出力 `comparison` object・`report` string・`warnings` array

## 5. プロンプト
### 5-1. System（`extract`）
```text
あなたは購買見積書から項目を抽出する抽出器です。文書に書かれている値だけを、書かれている単位・通貨・税区分のまま JSON に写します。
守ること：換算しない。推定しない。書かれていない項目は null。複数品目があれば配列にする。数値は文字列でなく数値型、単位は別フィールド。出力は JSON のみ（前後に文章を付けない）。
```
### 5-1b. System（`compose`）
```text
あなたは青嶺精工 蘇州工場 購買課のアシスタントです。Code ノードが正規化した比較データ（JSON）を、購買担当者が課長に報告できる比較表と説明に変換します。
守ること：
1. 数値は JSON の値をそのまま転記する。自分で計算・換算しない。
2. 値上げ妥当性は JSON の fair_increase_pct と出典（rule_source, market_note）を引いて書く。市況が無ければ「判定材料なし」。
3. 「最安」「候補」は言えるが、推奨サプライヤーの決定はしない。決定は購買課長。
4. null の項目は「記載なし・要確認」と書き、補わない。
5. カタログ値は「未検証」を付す。
6. サプライヤー向け文面を書くときは他社名を出さない。前回発注価格も書かない。
7. 出力言語：ユーザーの入力言語で答える。日本語なら日本語、中国語なら中国語。サプライヤー向け文面は target_lang。
出力形式：見出し「比較表」「値上げ妥当性」「交渉ポイント」「要確認」。
```
### 5-2. User テンプレート（`compose`）
```text
【比較条件】年間 {{start.annual_qty}} / 基準 {{start.base_currency}} {{start.tax_basis}} / 為替 {{normalize.fx_used}}
【正規化済み比較データ（転記のみ）】{{normalize.result}}
【前回発注】{{http.previous}}
【社内ルール（KB）】{{knowledge.result}}
【市況メモ（担当者入力）】{{start.market_note}}
比較表と説明を作成してください。
```
### 5-3. 出力フォーマット（後工程・xlsx 用）
```json
{
  "item_spec": "string",
  "base": {"currency": "RMB", "tax": "excl", "annual_qty": 2400, "fx": {"USDRMB": 7.15, "as_of": "YYYY-MM-DD"}},
  "suppliers": [{
    "name": "string", "source_file": "string",
    "raw": {"unit_price": 24.10, "currency": "USD", "per": "piece|box", "pack_size": 1, "tax": "excl|incl|null", "moq": 100, "lead_time_days": 42, "payment_terms": "string|null", "life_catalog": 250, "life_actual": null},
    "normalized": {"unit_price": 172.4, "annual_total": 413760, "vs_previous_pct": null, "cost_per_workpiece": 0.690},
    "flags": ["catalog_life_unverified", "prepayment"]
  }],
  "fair_increase_pct": 5.4, "rule_source": "string", "warnings": ["string"]

```
### 5-4. Few-shot
- **ja**：抽出入力「10支/盒 1,780元（含税13%）」→ `{"unit_price":1780,"currency":"RMB","per":"box","pack_size":10,"tax":"incl","tax_rate":0.13}`（本あたり・税抜への換算は Code）
- **zh**：`compose` 入力 `fair_increase_pct: 5.4, requested_increase_pct: 7.5` → 「涨价合理性：按公司材料构成比（钨约 30%，出处：采购备忘 2025-04）与担当输入的钨价 +18% 计算，合理涨幅约 +5.4%。S 刀具提出的 +7.5% 高出约 2 个百分点」

## 6. 検証観点
| 観点 | 基準 | 測り方 |
|---|---|---|
| 抽出の正確性 | 単価・通貨・単位・税区分・MOQ・納期の抽出一致 ≥ 95%（フィールド単位） | 評価セット 30 見積（ダミー）を人手採点 |
| 正規化の正確性 | Code 出力と手計算の一致 100% | 単体テスト（pytest 相当を Code 内サンプルで） |
| 転記の忠実性 | `compose` の数値が JSON と全件一致 | 正規表現で金額抽出→差分 |
| 未記載の扱い | null を補わない 100% | 負例セット（税区分なし・通貨なし） |
| 言語 | 入力言語で返答 100%、サプライヤー文面は target_lang | 自動判定 |
| 秘匿 | 交渉文に他社名・前回価格が出ない 100% | 文字列検査 |
| 速度 | 3 ファイルで p95 < 60 秒 | Langfuse |

- **評価方法**：リリース前に購買 2 名で 30 件人手。月次で Langfuse データセット＋LLM-as-judge（転記忠実性・秘匿）

## 8. 別出しが必要なもの（このサービス固有の準備）
- **前回発注価格の参照**（`PC-04`）：購買台帳（Excel か基幹）から品目コードで 1 行返す API。無い間は担当者がフォームに手入力
- **材料構成比・値上げ判断基準のメモ**（Outline → `PC-05` → KB）：品目カテゴリ別の主材料と構成比（購買課の経験値）。無いと妥当性判定が出ない
- **品目コード・規格の正規化辞書**（`PC-06`）：「硬质合金钻头／超硬ドリル／carbide drill」を同一品目に寄せる
- **市況の取得**：Web 検索ツール（`tools/searxng` 等）は中国本土からの到達性が未確定。当面は担当者入力
- **無くても動く範囲**：`PC-04`・KB 無しでも「抽出→正規化→比較表」は動く（前回比・妥当性が空欄になるだけ）。ここから始める

## 9. Outline Wiki との関係
- **読む**：`PC-05` で「購買規程」「材料構成比メモ」「サプライヤー評価基準」コレクションを KB `nm-purchase-rules` に同期
- **書く**：しない。比較表・交渉メモは案件ごとの機密で、購買課のファイル共有（`PC-13` 出力先）に置く。将来「交渉の落としどころ・結果」を Outline のサプライヤーページに人が転記する運用は候補（未確定）

## 10. 未確定・リスク
- **前回価格の所在**（基幹か Excel か）— 未確定。推奨：Excel の購買台帳を `tools/microsoft_excel_365` で読む最小構成から
- **為替レートの日付**：見積日と比較日でレートが違う。推奨：社内月次レートを既定、出力に `as_of` を必ず表示
