## 1. 業務シナリオ
- **いつ起きるか（トリガー）**：顧客（K 社）から新規部品・派生品の見積依頼（RFQ）が来たとき、担当者が能動的に開く。③業務フィードでは `due`（RFQ 回答期限）
- **登場人物**：営業駐在員（入力・提出判断）、生産技術（工程・加工時間の確認）、財務（原価テーブル・為替の正）、工場長（利益率の決裁）、外部：顧客 K 社（希望単価）、塗装外注 S 社（外注費）
- **いまの手順（Before）**：営業が図面を生産技術に回し、工程と SPH を口頭で聞く（半日〜1 日待ち）→ Excel の原価表を手でコピーして材料費・加工費・金型償却を計算（1〜2 時間）→ 過去の類似品見積をファイルサーバで探す（見つからないことが多い）→ 通貨・セット単価の取り違えに気づかず提出し、後で訂正する事故が年数回
- **エージェント導入後の手順（After）**：
  1. 営業が**フォームに入力**：図面番号・品名・材質・板厚・月産数量・期間・特記（塗装／金型新規／顧客希望単価）
  2. エージェントが原価テーブル（`PC-04` 経由）と類似見積 KB を引き、**Code ノードで**積み上げ計算・USD 換算・感度（為替 ±5%、材料 ±10%）を出す
  3. LLM は**計算結果を転記して説明**し、類似品との乖離（桁・単位の取り違え疑い）を「確認事項」として指摘する
  4. **人が決める場所**：工程数・SPH は生産技術が確認して**修正入力**、利益率は工場長が決める。エージェントは「ドラフト・参考値」しか出さない
  5. 確定後、見積書ドラフト（xlsx／pdf）を `PC-13` で出力し、営業が K 社へ提出
- **成功の定義**：初回ドラフトまでの時間 1 日 → 30 分。単位・通貨の取り違えによる訂正 0 件。類似品比較が毎回付く

## 3. 観点（LLM に守らせる業務ルール）
- **数値を作らない**：材料費・加工費・償却・合計・USD 換算・感度は **Code ノードの出力をそのまま転記**する。LLM が四則演算をしない。転記した数値には算出根拠（テーブルの行名・レート・版）を添える
- **乖離の指摘は必ず「確認事項」として**：類似品単価との桁差・セット／個の取り違え・通貨違いを検出したら断定せず「〜の可能性があります。入力を再確認してください」
- **原価テーブルにない項目は推定しない**：「原価テーブルに該当行がありません（材質 X）。財務に追加を依頼してください」
- **利益率・提出価格を決めない**：社内標準（例 15%）を「標準値」と明記し、変更は工場長決裁である旨を毎回書く
- **禁止**：顧客希望価格に合わせて原価を逆算する／他社（S 社・T 社）の購買単価を顧客向け見積書に転記する／原価テーブルの生値を見積書（社外文書）に載せる
- **不確実時の定型文**：「本試算はドラフト・参考値です。工程・加工時間は生産技術、原価テーブルと為替は財務の確認が必要です」（毎回末尾に付ける）
- **出力形式**：内部向け＝原価内訳表（Markdown 表）＋確認事項＋感度。見積書ドラフト＝§5-3 の JSON → `PC-13` で xlsx/pdf 化

## 4. Dify 構成
- **アプリ種別**：**Workflow**（フォーム 1 回実行で決定的な計算を返す。追加質問は Chatflow 版を後で重ねる）。デモの多輪台本は `templates/05` の Chatflow 内フォーム方式でも実現可
- **ノード列**：
  1. Start（`drawing_no` text 必須／`part_name` text／`material` select／`thickness_mm` number 必須／`monthly_qty` number 必須／`months` number 必須／`painting` select／`new_tooling` select／`target_price` text／`notes` paragraph／`doc_lang` select）
  2. LLM（`normalize`）：`target_price` の単位・通貨を JSON に正規化（`{amount, currency, per:"piece"|"set", set_size}`）。不明は `null`
  3. HTTP Request（`PC-04`）：原価テーブル JSON・社内レートを GET。失敗時 → If/Else → End（エラー文言）
  4. Knowledge Retrieval（KB `nm-quotes`、メタデータフィルタ `series = 図番系列`、top-k 3）：類似品の見積・単価
  5. **Code（Python）`costing`**：材料費（展開寸法×板厚×比重÷歩留×kg 単価）・加工費（工程数×3600/SPH×レート）・外注費・償却（金型費÷総数量）・検査包装物流・小計・販管費利益・USD 換算・感度表・**類似品との比率チェック**（比率 > 3 または < 1/3 で `unit_mismatch_suspect = true`）を JSON で返す
  6. LLM（`explain`）：Code の JSON を転記して説明。確認事項を列挙。§5 のプロンプト
  7. Template Transform：見積書ドラフト JSON（§5-3）→ `PC-13`
  8. End（`cost_breakdown` JSON／`explanation` string／`quote_draft` JSON／`warnings` array）
- **Knowledge**：`nm-quotes`（過去見積・原価内訳。`dify_extractor` でページ単位。メタ：`customer`／`series`／`year`／`price_unit`）。更新は四半期に財務がフォルダ投入（Knowledge Pipeline、データソース SharePoint or `tencent_cos_storage`）。原価テーブル本体は **KB に入れない**（API で Code に渡す）
- **プラグイン／ツール**：HTTP リクエストノード（本体）／Code ノード（本体）／`tools/dify_extractor`（KB 投入）／`tools/paddleocr` or `tools/mineru`（図面表題欄、任意）／`tools/microsoft_excel_365`（見積書 xlsx 出力、任意）。複雑計算に `tools/e2b` は**使わない**（SaaS・越境。Code ノードで足りる）
- **モデル**：既定 `models/siliconflow` Qwen3-235B-A22B-Instruct（`api.siliconflow.cn`）。`normalize` は Qwen3-32B で可。代替：DeepSeek-V3.x。越境ゼロが要件なら `models/ollama` Qwen（`PC-08`）
- **参照 DSL**：`../templates/07-excel-document-extractor-echarts.yml`（Start 変数→Code→LLM の骨子）、`../templates/05-chatflow-form-input-demo.yml`（多輪フォーム版）、`../templates/06`（HTTP で外部 API を呼ぶ型）
- **入出力変数**：

| 変数 | 型 | 必須 | 備考 |
|---|---|---|---|
| `drawing_no` / `material` / `thickness_mm` / `monthly_qty` / `months` | string / select / number / number / number | 必須 | 数値は 0 超 |
| `painting` / `new_tooling` | select（yes/no） | 必須 | |
| `target_price` / `notes` | string | 任意 | 単位は LLM で正規化 |
| `doc_lang` | select（ja/zh/en） | 任意 | 見積書の言語。既定は入力言語 |
| `cost_breakdown` | object | 出力 | Code の JSON |
| `quote_draft` | object | 出力 | §5-3 |
| `warnings` | array\<string\> | 出力 | 単位疑い・テーブル欠落 |

## 5. プロンプト
### 5-1. System（`explain` ノード）
```text
あなたは青嶺精工 蘇州工場の見積担当を補助するアシスタントです。
役割：Code ノードが計算した原価内訳（JSON）を、営業担当者が読める説明に変換し、確認すべき点を指摘します。
守ること：
1. 数値は必ず入力 JSON の値をそのまま転記する。自分で計算・丸め・換算をしない。JSON に無い数値を書かない。
2. 各金額に算出根拠（テーブル行名・レート・版）を添える。
3. warnings に unit_mismatch_suspect があれば「類似品単価との乖離」を確認事項の先頭に置き、「〜の可能性があります」と断定を避けて書く。
4. 利益率・提出価格は決めない。標準値である旨と、変更は工場長決裁である旨を書く。
5. 原価テーブルにない項目は推定せず「テーブルに該当行がありません」と書く。
6. 出力言語：ユーザーの入力言語で答える。日本語なら日本語、中国語なら中国語。
7. 末尾に必ず次の 1 行を入れる：「本試算はドラフト・参考値です。工程・加工時間は生産技術、原価テーブルと為替は財務の確認が必要です。」（中国語：「本试算为草案・参考值。工艺与加工时间需生产技术确认，成本表与汇率需财务确认。」）
出力形式：見出し「原価内訳」「類似品との比較」「確認事項」「感度」の順。表は Markdown。
```

### 5-4. Few-shot
- **ja**：入力「希望単価 USD 4.60」＋ Code 出力 `unit_price_usd: 1.04, similar: {SK-3310-A: 4.20}, unit_mismatch_suspect: true` → 期待出力の要点：「確認事項 1：類似品 SK-3310-A の単価 USD 4.20 と本試算 USD 1.04 に約 4 倍の差があります。SK-3310-A の単価がセット（複数個）価格である可能性があります。入力の単位を再確認してください」

## 6. 検証観点
| 観点 | 基準 | 測り方 |
|---|---|---|
| 計算の正確性 | Code 出力と財務 Excel の手計算が一致 100%（丸め誤差 ±0.01 RMB） | 評価セット 20 件を財務が照合 |
| 転記の忠実性 | LLM 出力の数値が Code JSON と全件一致（LLM が数値を作らない） | 数値抽出の自動比較（正規表現で金額を抜き、JSON と差分） |
| 乖離検出 | 単位・通貨の取り違えを含む 10 件で warnings を出す ≥ 95% | 負例セット |
| 網羅 | 原価内訳 6 項目・根拠・確認事項・末尾定型文の欠落 0 | チェックリスト |
| 言語 | 入力言語で返答 100% | `PC-07` の自動判定 |
| 形式 | `quote_draft` がスキーマ準拠 100% | JSON バリデータ |
| 安全 | 購買単価（S 社・T 社）が `quote_draft` に混入 0 | 負例セット・文字列検査 |
| 速度 | p95 < 40 秒（HTTP＋KB＋LLM 2 回） | Langfuse（`PC-09`） |

- **評価方法**：リリース前に人手（財務・生産技術）で 20 件、以後月次で Langfuse データセット＋LLM-as-judge（転記忠実性）。原価テーブル改定時は全件再実行

## 8. 別出しが必要なもの（このサービス固有の準備）
- **原価テーブルの構造化と API 化**（`PC-04`）：財務 Excel → JSON（材料 kg 単価・工程レート・償却ルール・販管費率・版・適用日）。これが**st3 の最大の壁**
- **為替レートの正**（`PC-04`）：社内レートの取得元と更新頻度
- **過去見積の KB 化**（`PC-03`）：単価の単位（個／セット）をメタデータに持たせる。これが無いと乖離検出が効かない
- **見積書テンプレート**（`PC-13`）：xlsx 雛形（日・中・英）と社印・担当欄
- **権限**（`PC-02`）：原価内訳は営業・生産技術・財務・工場長のみ
- **無くても動く範囲**：原価テーブルを**フォームから直接入力**（材料 kg 単価・レート・償却額）する版なら、`PC-04` 無しで Code 計算＋説明まで動く。類似品 KB が無ければ乖離検出は省き「比較対象なし」と出す。この最小版で計算ロジックと転記忠実性を先に検証する
