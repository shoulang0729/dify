## 1. 業務シナリオ

- **いつ起きるか（トリガー）**：担当者が能動的に開く（稟議の審査プロセスの中で）。③業務フィードでは `due`（稟議の審査期限）
- **登場人物**：審査部の次長・担当者（コメントを作成する側）、営業第一部（稟議の起案者）、与信先
- **いまの手順（Before）**：審査担当者が財務データ・案件資料を読み込み、過去の類似案件でどのような指摘がされたかを記憶や個別検索に頼りながらコメントを作成する。過去の指摘（担保の再評価要求等）の見落としが起きうる
- **エージェント導入後の手順（After）**：
  1. 財務データと案件資料をアップロードする
  2. 過去の審査結果・審査コメントの書き方に沿ったドラフトが、数字の根拠と過去に同じ業種で指摘された論点とともに返る
  3. 審査担当者が**内容を確認し、審査コメントとして確定する**（AI は確定しない）
- **成功の定義**：ドラフト作成の時間が減り、過去の類似案件で求められた条件（担保の再評価など）の見落としが無くなる

## 2. 想定インプット

| 種類 | 形式 | 言語 | 量・頻度 | 例 | 取得元 | 前処理 |
|---|---|---|---|---|---|---|
| 財務データ | xlsx | ja / zh | 案件ごと 1 件 | 財務データ_丙社_2026年6月期.xlsx | 与信先から受領 | `tools/dify_extractor`（行レコード化） |
| 稟議資料 | PDF | ja / zh | 案件ごと 1 件 | 稟議資料_RNG-2026-0089.pdf | 営業第一部が起案 | `Document Extractor`（PDF → テキスト） |
| ネガティブ情報 | 構造化データ | — | 任意 | `RS-01` の収集結果 | `RS-01` の出力（あれば取得） | 審査上の重要度の一次判定材料として参照 |
| 過去の類似案件の指摘事項 | Markdown | ja | 蓄積 | 前回の類似稟議で担保の再評価が求められた | Outline「審査コメントアーカイブ」コレクション（`PC-05`） | 業種・案件種別で絞って参照 |
| 延滞率等の全行 KPI | 数値 | — | 月次 | 延滞率 0.95%（目標 0.80%） | `data/world/fin/kpi.csv` 相当（本番は KPI マスタ） | 個社の状況と全行傾向を区別する材料 |

- **入力言語の扱い**：アップロードされる財務データ・案件資料は日本語・中国語どちらもあり得る。**審査コメント案は日本語**が既定（審査部の決裁が日本語で行われる前提。台本参照）。担当者とのやり取りは入力言語に従う（`CLAUDE.md` §2-5）
- **入力の欠け・曖昧さ**：過去の類似案件が見つからない場合は「過去の類似案件は見つかりませんでした」と明示する。ネガティブ情報（`RS-01`）が無い場合は「ネガティブ情報のチェックは実施していません」と明示し、チェック済みと誤認させない

## 3. 観点（LLM に守らせる業務ルール）

- **財務所見は数値の根拠を示す**：粗利率の変動などは、財務データ・セクター調査の該当箇所を根拠として示す
- **ネガティブ情報の重要度を勝手に格上げしない**：`RS-01` で軽微と分類された情報を、審査コメントで重大な懸念として扱わない（逆に軽視もしない。事実をそのまま転記する）
- **過去の類似案件での指摘は必ず確認し、反映する**：担保の再評価要求など、過去に同種の案件で求められた条件があれば審査コメント案に含める
- **審査コメント案は「案」であることを明示する**：**次長・担当者自身の確認と確定を必ず促す**。AI が確定しない
- **禁止**：財務データに無い数値を作る／過去の指摘事項を無視する／審査の可否を断定する（「支障なしと判断する」という文言はドラフトとして提示するが、あくまで案であり確定は人が行うことを明記する）
- **不確実なとき**（入力言語で）：ja「過去の類似案件は見つかりませんでした。一般的な観点でのコメント案です。」／zh「未找到过往类似案件，以下为基于一般观点的意见草案。」
- **出力の粒度**：与信先概要 → 財務所見 → ネガティブ情報 → 過去の類似案件での指摘 → 審査コメント案 → 確定前の確認

## 4. Dify 構成

- **アプリ種別**：**Workflow**（ファイルアップロード → 抽出 → ドラフト生成）
- **ノード列**：
  1. `Start`（財務データ xlsx、稟議資料 PDF）
  2. `tools/dify_extractor`（xlsx → 行レコード）／`Document Extractor`（PDF → テキスト）
  3. `HTTP Request`（`RS-01` の当該与信先のネガティブ情報を取得。無ければ空）
  4. `HTTP Request`（`PC-05` から過去の類似案件の指摘事項を取得。案件種別で絞る）
  5. `LLM`（審査コメント案の生成。§5 のプロンプト）
  6. `Code`（検算：過去の指摘事項が反映されているか、「案」の明記があるか）
  7. `Answer`
- **Knowledge**：使わない（過去の指摘事項は Outline から直接取得。財務データは都度アップロード）
- **プラグイン／ツール**：`Document Extractor ノード`、`tools/dify_extractor`（`../plugins-and-references.md` §1）、Outline API（過去案件の検索）
- **モデル**：既定 `models/siliconflow` Qwen3-235B-A22B-Instruct（審査コメントの文章生成。日本語品質は評価セットで確認。`PC-08`）
- **参照 DSL**：`../templates/07-excel-document-extractor-echarts.yml`
- **入出力変数**：

  | 名前 | 型 | 必須 | 説明 |
  |---|---|---|---|
  | `client_id` | string | ✓ | 与信先（`data/world/fin/clients.csv` の記号） |
  | `case_no` | string | ✓ | 稟議番号（`RNG-YYYY-NNNN`） |
  | `financial_file` | file | ✓ | 財務データ |
  | `case_file` | file | ✓ | 稟議資料 |
  | 出力 `comment_draft` | string | ✓ | 審査コメント案 |
  | 出力 `past_findings` | array[object] | — | 過去の類似案件での指摘事項 |

## 5. プロンプト

### 5-1. System

```text
あなたは碧洋銀行 審査部の審査コメントドラフト作成アシスタントです。
与信先（{{client_id}}）の稟議（{{case_no}}）について、財務データ・稟議資料・ネガティブ情報（{{rs1_json}}）・
過去の類似案件での指摘事項（{{past_findings}}）から、審査コメント案を作成します。
守ること：
1. 財務所見は財務データ・稟議資料の該当箇所を根拠として示す。無い数値を作らない。
2. ネガティブ情報の重要度は与えられた分類（軽微／重大）をそのまま転記する。自分で格上げ・格下げしない。
3. 過去の類似案件での指摘事項があれば、審査コメント案に必ず反映する（例：担保の再評価）。
4. 審査コメント案は「案」であり、確定は次長・担当者自身が行う旨を必ず末尾に書く。
5. 過去の類似案件が見つからないときは「一般的な観点でのコメント案」であることを明記する。
6. 言語：審査コメント案は日本語。担当者とのやり取りは入力言語（日本語なら日本語、中国語なら中国語）で答える。
出力：与信先概要 → 財務所見 → ネガティブ情報 → 過去の類似案件での指摘 → 審査コメント案 → 確定前の確認 の順。
```

### 5-2. User テンプレート

```text
与信先={{client_id}}／稟議={{case_no}}
財務データ（転記のみ）：{{financial_json}}
稟議資料（本文）：{{case_text}}
ネガティブ情報（RS-01。無ければ「未実施」）：{{rs1_json}}
過去の類似案件での指摘事項（Outline から取得）：{{past_findings}}
全行 KPI（比較材料。転記のみ）：{{bank_kpi_json}}
```

### 5-3. 出力フォーマット

```json
{
  "client_id": "丙社", "case_no": "RNG-2026-0089",
  "profile": "既存与信の延滞履歴なし。当行全体の延滞率は0.95%（目標0.80%）と悪化傾向だが丙社個社は該当なし。",
  "financial_finding": "直近期の粗利率は前期比やや低下（原材料コスト上昇が主因）。",
  "negative_info": { "checked": true, "summary": "軽微な行政指導（環境規制・是正済み）。重大な懸念材料ではない" },
  "past_findings": [ { "case_no": "RNG-2026-0089（起案時）", "requirement": "担保（工場設備）の再評価" } ],
  "comment_draft": "原材料コスト上昇による粗利率低下は業界共通の一時的要因と評価。担保の再評価を条件に、極度額の見直しに支障なしと判断する（案）。",
  "confirm_note": "この文言で審査コメントとして確定してよいか、次長ご自身でご確認ください"
}
```

### 5-4. Few-shot

**不要**。案件ごとに財務状況・過去の指摘が異なるため、書式は System と JSON スキーマで固定する。

## 6. 検証観点

| 観点 | 基準 | 測り方 |
|---|---|---|
| 数値の根拠 | 財務所見の数値に根拠箇所が付く 100% | スキーマバリデータ |
| ネガティブ情報の転記 | 重要度の格上げ・格下げ 0 件 | 自動突合 |
| 過去の指摘の反映 | 該当する過去案件がある場合に反映 100% | 人手 |
| 案である旨の明記 | `confirm_note` が全件に付く 100% | 自動 |
| 言語 | コメント案は日本語、やり取りは入力言語 100% | 自動判定（`PC-07`） |
| 拒否 | 過去案件なしの明示 100% | 自動 |
| 速度 | p95 < 40 秒 | Langfuse |

- **評価方法**：リリース前に審査部で 15 件を人手採点

## 8. 別出しが必要なもの

- `PC-05`：「審査コメントアーカイブ」コレクションに過去の審査コメント・指摘事項を保存。案件種別・業種で検索できるようにする
- `PC-03`：財務データ・稟議資料の抽出
- `RS-01`：ネガティブ情報の取得先（あれば使う。無くても動く）
- **無くても動く範囲**：過去案件アーカイブが無くても、財務所見・ネガティブ情報のみのコメント案は作成できる（過去の指摘の反映ができないだけ）

## 9. Outline Wiki との関係

- **読む**：「審査コメントアーカイブ」コレクションの過去の審査コメント・指摘事項（`PC-05`）
- **書く**：候補・未確定。確定した審査コメントを次回のアーカイブとして残すかは審査部の運用ルール次第（確定後の書き込みは人が行う想定）
- 与信先の財務データそのものは Wiki に書かない

## 10. 未確定・リスク

- **実現性を ○ とした理由**：ファイルアップロード・抽出・ドラフト生成は標準機能で足りるが、(1) 過去の審査コメントアーカイブの整備状況、(2) 審査コメントの「良し悪し」の評価がモデル差・人手評価に依存する、の 2 点で ◎ にしていない
- **審査コメントアーカイブの正本化**：現状は Outline のコレクション案のみ。確定コメントの書き込みフロー（誰が・いつ）は審査部の運用ルールとして別途決める必要がある
- **RS-01 との連携**：与信先ごとの監視設定が無い場合、CV-03 実行時にオンデマンドでネガティブ情報を検索するか、「未実施」のまま進めるかは未確定（本ファイルは後者を既定とした）
