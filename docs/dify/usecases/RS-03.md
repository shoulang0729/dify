## 1. 業務シナリオ

- **いつ起きるか（トリガー）**：担当者が能動的に開く（与信更新・面談準備の前）。③業務フィードでは `due`（与信更新期日に紐づく準備作業）
- **登場人物**：法人営業の担当者（資料を整理する側）、与信先の親会社（日本本社。上場企業が多い）、審査部（同資料を与信更新の判断材料として使う）
- **いまの手順（Before）**：担当者が親会社の決算短信・有価証券報告書を自分で読み込み、必要箇所を訳しながら要約する。過去期との比較や同業比較は手作業の Excel 集計で、時間がかかる上に抜けが出やすい
- **エージェント導入後の手順（After）**：
  1. 決算短信・有価証券報告書などをアップロードする
  2. 日本語要約と、過去期との比較表・同業他社との並べ方が自動で返る
  3. 担当者が与信先（中国現地法人）への言及箇所を確認し、**与信更新資料に添付する形に整える**（AI は与信判断をしない）
- **成功の定義**：決算資料の読み込み・要約・比較表作成にかかる時間が大幅に減り、面談・与信の下準備がそのまま使える資料として残る

## 2. 想定インプット

| 種類 | 形式 | 言語 | 量・頻度 | 例 | 取得元 | 前処理 |
|---|---|---|---|---|---|---|
| 決算短信・有価証券報告書 | PDF | ja | 与信先ごと年 1〜4 回（四半期） | 決算短信_乙社日本本社_2026年3月期.pdf | 担当者が公開情報からダウンロードしてアップロード | `Document Extractor` → `PC-03`（`tools/dify_extractor`。ページ単位） |
| 過去期の要約結果（比較用） | JSON／Markdown | ja | 与信先ごと蓄積 | 前々期・前期の要約 | 本サービスの過去出力（§8 のストア） | 今回の数値との比較に使う |
| 同業比較の指標（外部リサーチ） | 数値 | ja | 任意 | 商社セクター平均営業利益率 6.8% | 外部リサーチ（担当者が併せて提供、または RS-02 の観点を流用） | Code で比較表に組み込む |

- **入力言語の扱い**：アップロードされる決算資料は日本語が前提（親会社が日系上場企業のため）。要約・比較表は**日本語**で返す（`CLAUDE.md` §2-5 の原則どおり、担当者とのやり取りは入力言語に従う）
- **入力の欠け・曖昧さ**：過去期のデータが無い（初回）場合は「過去期との比較なし」と明示し、今期の要約のみを返す。中国事業単体の数値が開示に無い場合は「開示情報からは推計できません」と明記し、推測で埋めない

## 3. 観点（LLM に守らせる業務ルール）

- **与信先への言及箇所を必ず拾う**：セグメント情報・注記の中で、当該中国現地法人（与信先）に関わる記述があれば要約に含める
- **数値の増減には資料中の説明を紐づける**：「営業利益率が低下」だけでなく、資料に書かれている要因（原材料コスト等）を併記する
- **中国事業単体の数値が無いことを明示する**：開示が連結・セグメント単位までで、与信先単体の業績が分からない場合は「要確認」として明記し、推計しない
- **与信判断をしない**：「与信先の信用力にどう影響するか」を断定せず、判断材料（増収か減収か、収益性の変化）の提示にとどめる
- **禁止**：決算資料に無い数値を作る／同業比較の基準（サンプル企業・期間）を明示せずに数値だけ出す／中国事業と与信先個社を混同する
- **不確実なとき**（入力言語で）：ja「開示資料からは判断できません。中国事業単体の数値は開示されていない可能性があります。」／zh「无法从披露资料中判断。中国业务单体的数字可能未被披露。」
- **出力の粒度**：要約（3〜5 行）→ 与信先への言及 → 過去期との比較表 → 同業比較 → 要確認事項

## 4. Dify 構成

- **アプリ種別**：**Workflow**（ファイルアップロード → 抽出 → 要約・比較 → 出力）
- **ノード列**：
  1. `Start`（ファイル：決算短信・有価証券報告書。複数可）
  2. `Document Extractor`（PDF → テキスト。ページ単位で保持）
  3. `LLM`（軽量）— 財務諸表・セグメント情報・注記から主要指標（売上高・営業利益・営業利益率）と与信先への言及箇所を抽出。JSON 出力
  4. `HTTP Request`（§8 のストアから過去期の抽出結果を取得）
  5. `Code`（今期・過去期・同業平均の比較表を組み立て。増減率・トレンドの計算）
  6. `LLM`（本体）— 要約・与信先への言及の解説・比較表の読み解き。§5 のプロンプト
  7. `HTTP Request`（§8 のストアに今期の抽出結果を保存。次回比較用）
  8. `Answer`（要約・比較表・要確認事項）
- **Knowledge**：使わない（決算資料は都度アップロードで、与信先ごとの過去期データは §8 のストアに構造化して持つ。財務用語の対応表は `PC-06` から注入）
- **プラグイン／ツール**：`Document Extractor ノード`、`tools/dify_extractor`（`../plugins-and-references.md` §1。ページ単位レコード）
- **モデル**：既定 `models/siliconflow` Qwen3-235B-A22B-Instruct（要約・比較の解説）／Qwen3-32B（指標抽出）。日本語の要約品質は評価セットで確認（`PC-08`）
- **参照 DSL**：`../templates/07-excel-document-extractor-echarts.yml`（ファイル入口の型）、`../templates/04-trilingual-consistency-checker.yml`（過去期との突合の型）
- **入出力変数**：

  | 名前 | 型 | 必須 | 説明 |
  |---|---|---|---|
  | `files` | file[] | ✓ | 決算短信・有価証券報告書 |
  | `client_id` | string | ✓ | 与信先（`data/world/fin/clients.csv` の記号） |
  | `peer_avg` | object | — | 同業比較の外部数値（任意） |
  | 出力 `summary_ja` | string | ✓ | 要約 |
  | 出力 `comparison_table` | object | ✓ | 過去期・同業比較 |
  | 出力 `to_confirm` | string[] | ✓ | 要確認事項 |

## 5. プロンプト

### 5-1. System

```text
あなたは碧洋銀行 営業第一部の顧客IR要約アシスタントです。
与信先（{{client_id}}）の親会社の決算資料を読み、日本語で要約し、過去期・同業他社との比較を行います。
守ること：
1. 要約は資料本文からのみ作る。資料に無い数値を作らない。
2. 数値の増減には、資料に書かれている要因の説明を必ず紐づける。
3. 与信先（中国現地法人）への言及箇所（セグメント情報・注記）があれば必ず要約に含める。
4. 中国事業単体の数値が開示に無い場合は「開示情報からは推計できません」と明記し、推計しない。
5. 与信先の信用力への影響を断定しない。判断材料（増収/減収、収益性の変化）の提示にとどめる。
6. 同業比較を出すときは、比較対象・期間の出所を明記する。
7. 過去期のデータが無いときは「過去期との比較なし」と書く。
8. 言語：要約は日本語。担当者とのやり取りは入力言語（日本語なら日本語、中国語なら中国語）で答える。
出力：要約 → 与信先への言及 → 過去期との比較表 → 同業比較 → 要確認事項 の順。
```

## 6. 検証観点

| 観点 | 基準 | 測り方 |
|---|---|---|
| 正確性 | 要約の数値が資料本文と一致 ≥ 95% | 評価セット 15 件を人手採点 |
| 要因の紐づけ | 数値の増減に説明が付く 100% | スキーマバリデータ |
| 与信先言及の網羅 | セグメント情報中の与信先関連記述の抽出漏れ 0 | 人手（負例含む） |
| 推計の禁止 | 開示に無い中国事業単体の数値を作らない 100% | 負例セット |
| 言語 | 要約は日本語、やり取りは入力言語 100% | 自動判定（`PC-07`） |
| 拒否 | 過去期データ無しの明示 100% | 自動 |
| 速度 | p95 < 40 秒（複数 PDF） | Langfuse |

- **評価方法**：リリース前に営業第一部・審査部で 15 件を人手採点。月次で Langfuse のスコア確認

## 8. 別出しが必要なもの

- **過去期抽出結果ストア**（本サービス固有）：与信先ごとの決算要約・主要指標を JSON で蓄積する小さなテーブル（`id`／`client_id`／`period`／`metrics_json`／`created_at`）。次回実行時にここを読んで比較する。第 1 段階は `tools/microsoft_excel_365` の表でも代替できる
- `PC-03`：決算資料（PDF）の抽出。ページ数が多い有価証券報告書は分割・並列抽出を検討
- `PC-06`：財務用語（セグメント情報・営業利益率 等）の日中対応（同業比較を中国語で出す場合に使う）
- `PC-13`：与信更新資料への添付シート出力
- **無くても動く範囲**：過去期抽出結果ストアが無くても、今期の要約のみは動く（比較ができないだけ）

## 9. Outline Wiki との関係

- 使わない。決算資料そのものは都度アップロードで、KB 化・Wiki 化しない（親会社の決算情報は更新頻度が高く、版管理を Outline で持つより都度読み込む方が実態に合う）。過去期の抽出結果は §8 の専用ストアで持つ
