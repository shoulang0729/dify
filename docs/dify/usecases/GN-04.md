## 1. 業務シナリオ
- **いつ起きるか（トリガー）**：来訪・監査・定例の振替など、日中の複数名の日程を合わせる必要が出たとき、担当者が能動的に開く（③業務フィードの `due`：来訪日）
- **登場人物**：総務担当（条件入力・候補の確定・招集送信）、参加者 8 名（日本本社 2・蘇州 6）、会議室管理（総務）、外部：サプライヤー・監査員（予定は見えない＝候補を提示して聞く）
- **いまの手順（Before）**：参加者の予定を Outlook／WeCom で個別に見て（見えない人にはチャットで聞く）→ 時差（中国＝日本 −1h）と両国の祝日・本社の休暇推奨日を手で照合 → 会議室を別途予約 → 日中 2 言語の招集メールを書く（1 時間）→ 1 名の予定変更で全部やり直し
- **エージェント導入後の手順（After）**：
  1. 担当者が**自然言語で条件**（参加者・所要時間・期間・オンライン／対面・優先度）を入力（ja/zh）
  2. Agent が **`PC-04` のカレンダーツールで参加者の空き（free/busy のみ）**を取得し、KB の祝日・休暇推奨日・定例会議と突き合わせ、**Code で候補時間帯を計算**（時差込み）
  3. LLM が候補 3 つを「全員可／一部不可（誰が・どの時間）」の根拠付きで提示
  4. **人が決める場所**：候補の選択・会議室の確定・招集の送信は担当者。エージェントは招集文（日中 2 言語）のドラフトまで。**予定の作成（create_event）・送信は担当者がボタンで実行**（AI が勝手に登録しない原則）
  5. 変更が入ったら同じ会話で再計算
- **成功の定義**：8 名の調整 1 時間〜半日 → 10 分。祝日・時差の取り違え 0。招集文の日中 2 言語が定型で揃う

## 3. 観点（LLM に守らせる業務ルール）
- **候補時間帯は Code の計算結果**（空き・祝日・定例・営業時間 9:00–18:00 各拠点・時差）。LLM が時刻を作らない。両拠点の時刻を必ず併記（中国 14:00 ／ 日本 15:00）
- **予定の中身を出さない**（`PC-10`）：他人の予定は「不可（13:00–17:00）」まで。件名・相手先・私用を書かない。台本の「K 社常熟訪問」のような件名は**本番では出さない**
- **参照できない人を全員可に含めない**。「参照可 6 名全員空き。参照不可 2 名は確認要」
- **予定作成・招集送信は担当者の操作**。「予約しました」「送信しました」と書かない。「予約する場合はボタンで実行」
- **祝日・休暇推奨日は KB の値のみ**（記憶で祝日を書かない。年により変わる）
- **禁止**：本人の許可なく外部（サプライヤー）に社内参加者の予定を見せる文面／優先順位（誰の予定を優先するか）を勝手に決める（提案はよい）
- **不確実時の定型文**：「{{period}} に全員が空く時間帯が見つかりません。参加者を減らす／期間を広げる／時間を短くする、のどれで再検索しますか」
- **出力形式**：候補 3 件（両拠点時刻・可否・不可の人と時間帯）＋制約の根拠（祝日・定例）＋招集文ドラフト（日中併記）＋操作ボタン（予約・送信は `PC-16`）

## 4. Dify 構成
- **アプリ種別**：**Chatflow 内 Agent ノード**（DSL 0.6.0 では Workflow/Chatflow 内の Agent ノード。`agent-strategies/cot_agent` Function Calling）。固定手順で足りる部分（候補計算）は Code ノードに置き、Agent はツール呼び出し（空き取得・会議室）に限定する（dsl-skill の指針：固定手順は通常 tool ノードの方が安定）
- **ノード列**：
  1. Start（`sys.query`）
  2. Parameter Extractor（`attendees[]`／`duration_min`／`period_from`／`period_to`／`mode`: online|onsite|hybrid／`room_site`）
  3. Code（`resolve_people`）：名簿（`PC-04` or KB）で社員 ID・拠点・タイムゾーン・カレンダー接続可否を解決。曖昧→Answer（聞き返し）
  4. **Agent ノード**（`cot_agent` FC。ツール：`tools/outlook` の予定一覧（free/busy 用途、日本本社）／中国側カレンダー（**未確定**：M365 なら同じ、WeCom・DingTalk なら `http-request` の自作ツール）／会議室空き）。指示：「各参加者の busy 区間だけを取得。件名・本文を返さない」
  5. Knowledge Retrieval（KB `gn-calendar-rules`：祝日・休暇推奨日・定例会議・会議室一覧・招集書式）
  6. **Code（`find_slots`）**：営業時間（各拠点）∩ 空き ∩ 非祝日 ∩ 非定例 で `duration_min` の連続枠を列挙、全員可を優先し一部不可は不可者と時間を付けて上位 3 件。参照不可の参加者は `unverified[]`
  7. LLM（`propose`）：候補提示・招集文ドラフト（§5）
  8. Answer（会話変数 `slots` JSON。担当者が候補を選んだ次ターンで `create_event` は **HITL（Human-in-the-loop）確認**を挟んでから Agent が実行 — 1.15.0 の human-input ノード）
- **Knowledge**：`gn-calendar-rules`（Outline 同期：日本・中国の祝日（年別）、本社休暇推奨日、蘇州の定例会議、会議室一覧（設備・定員）、招集メール書式）。予定データは **KB に入れない**
- **プラグイン／ツール**：`agent-strategies/cot_agent`／`tools/outlook`（M365：予定一覧・作成・メール下書き。Graph 権限はテナント管理者承認）／`tools/feishu_calendar`（`tools/feishu_*` の一つ。基盤が該当する場合のみ）／Google カレンダー用ツールは `../plugins-and-references.md` に無く**未確認**／**WeCom・DingTalk の予定表プラグインは公式に無い** → `http-request` 自作ツール（`PC-04`）／`tools/email` or `tools/wecom`（招集送信は人がボタン、`PC-14`）
- **モデル**：既定 `models/siliconflow` Qwen3-235B-A22B-Instruct（Function Calling 対応・日本語招集文）。代替 DeepSeek-V3.x。予定＝個人情報のため `models/ollama` も選択肢（`PC-08`）
- **参照 DSL**：該当なし（`../feasibility-33-services.md` §3 gn4：DSL・事例とも見つからず）。構成参考：`../templates/05-chatflow-form-input-demo.yml`（会話変数の持ち方）、`../templates/06`（`http-request` ツールの型）
- **入出力変数**：`sys.query` string 必須／会話変数 `slots` object・`selected_slot` object／出力 `answer` string・`invite_draft` object

## 5. プロンプト
### 5-1. System（`propose`）
```text
あなたは青嶺精工 蘇州工場 管理部の日程調整アシスタントです。Code ノードが計算した候補時間帯（JSON）と社内ルール（KB）から、候補の提示と会議招集文のドラフトを作ります。
守ること：
1. 候補の日時・可否・不可者は JSON の値をそのまま転記する。時刻を自分で計算しない。両拠点の時刻（中国時間／日本時間）を必ず併記する。
2. 他人の予定の中身（件名・相手・場所・私用）を書かない。「不可（13:00–17:00）」までにする。
3. unverified（予定を参照できない参加者）を「全員可」に含めない。「参照可 N 名は空き。参照不可の M 名（氏名）は先方確認」と書く。
4. 祝日・休暇推奨日・定例会議は JSON/KB にある根拠だけを引く。
5. 予定の作成・招集の送信を自分がしたと書かない。「予約／送信する場合は画面のボタンで実行してください」と書く。
6. 誰の予定を優先するかを決めない。提案（例：決裁者の全時間参加を優先する案）はよいが、判断は担当者。
7. 招集文は常に日本語と中国語の併記。KB の書式（件名／日時（両時間）／場所／参加／議題）に従う。
8. 出力言語（説明部分）：質問の言語。日本語なら日本語、中国語なら中国語。
出力形式：「候補」（① ② ③、各行に 中国 hh:mm–hh:mm ／ 日本 hh:mm–hh:mm、可否、不可者と時間）→「制約の根拠」→「招集文ドラフト（日／中）」→「次の操作」。
```
### 5-2. User テンプレート
```text
【依頼】{{sys.query}}
【参加者解決】{{resolve.people}}（接続可否含む）
【候補時間帯（Code 出力・転記のみ）】{{find_slots.result}}

【前回の候補（多輪）】{{conversation.slots}}
```

- **ja**：slots rank1 全員可・rank2 劉 10:00–10:30 不可 → 「① 9/18（木）中国 14:00–15:30 ／ 日本 15:00–16:30 — 参照可 8 名全員空き。2F B 会議室 空き。② 9/19（金）中国 10:00–11:30 ／ 日本 11:00–12:30 — 劉 技師が 10:00–10:30 不可。… 制約：日本 9/23 秋分の日（KB）、蘇州 毎週月曜 生産会議（KB）。予約・招集は画面のボタンで」

- **会議室リソース**（M365 リソースカレンダー or 予約台帳）
- **HITL 確認 UI**（`PC-16`、human-input ノード）：予約・送信の承認ボタン
- **無くても動く範囲**：カレンダー未接続でも、**参加者の「不可時間」を担当者がテキストで入力**すれば同じ Code で候補計算＋祝日照合＋招集文ドラフトが動く（「手入力版」）。デモ台本の再現もこれで可。接続は拠点ごとに段階追加

## 9. Outline Wiki との関係
- **読む**：`PC-05` で「祝日カレンダー（日・中、年別）」「本社休暇推奨日」「蘇州 定例会議」「会議室一覧」「会議招集書式」を KB `gn-calendar-rules` に同期
