## 1. 業務シナリオ

- **いつ起きるか（トリガー）**：担当者が能動的に開く（為替予約更新・市況確認などの都度）。③業務フィードには乗らない（定型の定例ではないため）
- **登場人物**：市場業務部の担当者（照会する側）、照会結果を使う法人営業・審査部門
- **いまの手順（Before）**：担当者が契約している金融情報端末（実在サービス名は伏せる。§7-3）や外部データベースの端末画面を都度操作し、必要な銘柄・指標・期間のデータを手作業で抜き出し、Excel に転記してから資料に使う
- **エージェント導入後の手順（After）**：
  1. 銘柄・企業・指標と期間を指定して照会する
  2. 契約しているデータ源からデータが取得され、表とグラフ用の数値で返る
  3. 担当者が**結果を営業資料・与信更新資料に使える形にまとめるかどうかを判断する**（AI は予約レートの確定・取引実行をしない）
- **成功の定義**：市況データの取得・転記にかかる時間が減り、営業第一部・審査部への提供が速くなる

## 2. 想定インプット

| 種類 | 形式 | 言語 | 量・頻度 | 例 | 取得元 | 前処理 |
|---|---|---|---|---|---|---|
| 照会条件 | クエリ文字列またはフォーム | ja / zh | 都度・1 日数件 | 人民元／日本円 3 か月先物レート 直近 6 か月 | 入力欄（`PC-16`） | 銘柄・指標・期間のパラメータ抽出（`Parameter Extractor`） |
| 市場・企業データ | JSON（API 応答） | — | 照会ごと | 直物レート・先物レート・月次系列 | 契約している金融情報端末・外部データベース（API） | `Code` で表形式・グラフ用配列に整形 |

- **入力言語の扱い**：照会文・追い質問は日本語・中国語のどちらでも受け、**入力言語で返す**（`CLAUDE.md` §2-5）
- **入力の欠け・曖昧さ**：銘柄・指標・期間のいずれかが不足していると照会できない旨を返す。**契約範囲外の項目**（例：将来予測）は取得せず、理由を明記して返す（推測で埋めない）

## 3. 観点（LLM に守らせる業務ルール）

- **取得したデータをそのまま示す**：数値の加工（補間・平均・予測）を LLM が行わない。表・グラフ用の数値は API 応答をそのまま使う
- **契約範囲外は明確に断る**：将来予測・非契約銘柄など、データ源から取得できない照会には「契約範囲外のため取得できません」と理由を返す。推測で数値を作らない
- **データ源を明示する**：どのデータ源（契約している金融情報端末／外部データベース）から取得したかを結果に必ず記載する
- **予約レート等の最終決定を代行しない**：市場業務部内の決裁が必要な数値（為替予約レートの確定等）は「参考情報」であることを明記する
- **禁止**：非契約データの推測での代替／取得元を隠した数値の提示
- **不確実なとき**（入力言語で）：ja「この照会は契約範囲外のため取得できません。市場業務部内のレポートか外部リサーチ会社への照会が必要です。」／zh「此查询超出合同范围，无法获取。需另行委托市场业务部内部报告或外部研究机构。」
- **出力の粒度**：照会結果（表）→ 前月比・変動幅などの注記（Code の計算値のみ）→ 利用上の注意（決裁が必要な旨）

## 4. Dify 構成

- **アプリ種別**：**Workflow**（`lookup` 型。`Start(query)` → 抽出 → 外部照会 → 整形 → 結果）
- **ノード列**：
  1. `Start`（`query` または銘柄・指標・期間のフォーム）
  2. `Parameter Extractor`（銘柄・指標・期間を抽出）
  3. `Code`（データ源の選択：契約している金融情報端末か外部データベースか。既定はフォームで選択済みの値）
  4. `HTTP Request`（`PC-04` のアダプタ経由でデータ源 API を照会。読み取り専用）
  5. `Code`（表・グラフ用の数値へ整形。前月比・変動幅の計算。**契約範囲外はここで検知**）
  6. `LLM`（軽量）— 結果の解説文を生成。§5 のプロンプト
  7. `Answer`（表・グラフ用数値・解説・データ源の明記）
- **Knowledge**：使わない
- **プラグイン／ツール**：**HTTP リクエストノード**（`../plugins-and-references.md` §6。ERP/MES 照会と同じ構成で、契約データ源へのアダプタ経由の読み取り専用接続に使う）、`Code` ノード（整形・計算）
- **モデル**：既定 `models/siliconflow` Qwen3-32B（解説文の生成のみ。数値計算は行わせない）
- **参照 DSL**：`../templates/06-text-to-sql-http-api-echarts.yml`（外部 API 照会 → 表・グラフの型）
- **入出力変数**：

  | 名前 | 型 | 必須 | 説明 |
  |---|---|---|---|
  | `instrument` | string | ✓ | 銘柄・通貨ペア |
  | `metric` | string | ✓ | 指標（直物レート・先物レート 等） |
  | `period` | string | ✓ | 期間 |
  | `data_source` | select | — | 契約している金融情報端末 / 外部データベース（既定：金融情報端末） |
  | 出力 `table` | object | ✓ | `columns`/`rows`（モックの `Result` 型） |
  | 出力 `source` | string | ✓ | 取得元の明記 |
  | 出力 `declined` | string[] | — | 契約範囲外で取得しなかった項目と理由 |

## 5. プロンプト

### 5-1. System

```text
あなたは碧洋銀行 市場業務部のデータ照会アシスタントです。
指定された銘柄・指標・期間について、契約しているデータ源から取得した数値（{{data_json}}）をそのまま表として示し、簡潔な解説を添えます。
守ること：
1. 数値は与えられた {{data_json}} をそのまま使う。自分で補間・平均・予測をしない。
2. 契約範囲外の照会（将来予測・非契約銘柄など）は、取得せず「契約範囲外のため取得できません」と理由を書く。
3. データ源（契約している金融情報端末／外部データベース）を必ず明記する。
4. 予約レート等、市場業務部内の決裁が必要な数値は「参考情報」である旨を明記する。
5. 言語：担当者とのやり取りは入力言語（日本語なら日本語、中国語なら中国語）で答える。
出力：照会結果の表 → 変動幅などの注記（計算値の転記のみ）→ 利用上の注意 の順。
```

### 5-2. User テンプレート

```text
照会：銘柄={{instrument}}／指標={{metric}}／期間={{period}}／データ源={{data_source}}
取得結果（Code 転記のみ）：{{data_json}}
declined（契約範囲外で取得できなかった項目）：{{declined}}
```

### 5-3. 出力フォーマット

```json
{
  "instrument": "人民元／日本円", "metric": "3 か月先物レート", "period": "直近6か月",
  "source": "金融情報端末（契約先データ源）",
  "table": { "columns": ["月", "直物レート", "3か月先物レート", "前月差"],
             "rows": [["4月","20.10","20.05","—"], ["9月（直近）","20.58","20.52","▲0.03"]] },
  "note": "最大変動幅+0.19／最小▲0.05。予約レートの最終決定は市場業務部内の決裁が必要です。",
  "declined": []
}
```

### 5-4. Few-shot

**不要**。照会内容ごとに数値が変わるため、書式は System と JSON スキーマで固定する。

## 6. 検証観点

| 観点 | 基準 | 測り方 |
|---|---|---|
| 数値の非改変 | 表の数値が API 応答と完全一致 100% | 自動突合 |
| 契約範囲外の検知 | 範囲外照会で declined が返る 100% | 負例セット |
| データ源の明記 | 結果に source が付く 100% | スキーマバリデータ |
| 決裁前提の明記 | 為替予約レート等に注意書きが付く 100% | 自動（キーワード検査） |
| 言語 | やり取りは入力言語 100% | 自動判定（`PC-07`） |
| 拒否 | 契約範囲外で定型文 ≥ 95% | 負例セット |
| 速度 | p95 < 10 秒 | Langfuse |

- **評価方法**：リリース前に市場業務部で 15 件（正常 10・範囲外 5）を人手採点。API 応答が固定モックのため自動突合が主

## 8. 別出しが必要なもの

- **金融情報端末・契約データベースへの接続アダプタ**：`PC-04` の実現案（`http-request` → アダプタ → 外部システム、読み取り専用アカウント）をそのまま適用するが、`../platform-components.md` PC-04 の「依存する外部システム」欄は現時点で QMS/BPMS/ERP/MES/WMS/稟議 WF のみで、**金融情報端末・契約データベースは含まれていない**。architect 側で PC-04 の対象システム一覧に追記するか、別出し先を検討する必要がある（§10）
- `PC-13`：照会結果を営業資料・与信更新資料へ添付する場合のファイル出力（任意）
- **無くても動く範囲**：接続アダプタが無い間は、担当者が端末から手動で数値を取得し、それを貼り付けて「表に整形して」と依頼する使い方でも成立する（照会の自動化ができないだけ）

## 10. 未確定・リスク

- **実現性を △ とした理由**：Dify 側のロジック（照会 → 整形 → 解説）自体は簡単だが、**外部の契約データ源（金融情報端末・データベース）への API 接続が前提**であり、(1) 契約先が API を提供しているか、(2) 中国拠点からの到達性、(3) データ利用許諾の範囲（再配布・保存の可否）の 3 点が未確認のため。これらが確認できるまでは「アップロード → 抽出」（担当者が端末から出力した CSV を渡す）に落とすのが現実的
- **`PC-04` の対象システム拡張**：`../platform-components.md` の PC-04 に金融情報端末・契約データベースを追記するかどうかは architect 判断（本ファイルでは提案のみ）
- **データ利用許諾**：取得したデータの再配布・保存期間・第三者提供の可否は契約条件に依存する。営業資料への転記が許諾範囲内かは法務・契約管理部門への確認が必要
