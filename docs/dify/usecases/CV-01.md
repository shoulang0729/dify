## 1. 業務シナリオ

- **いつ起きるか（トリガー）**：担当者が能動的に開く（新規開拓の検討時、セクター調査で機会を見つけたとき）。③業務フィードには乗らない
- **登場人物**：法人営業の部門長・担当者（提案資料を作る側）、候補先（未取引の企業）、既存与信先（比較対象）
- **いまの手順（Before）**：担当者が業種・規模・地域から候補先の当たりをつけ、公開情報を個別に調べ、過去の類似案件の資料を探して構成を真似ながら手作業で作成する。候補先の探索と資料構成の両方に時間がかかる
- **エージェント導入後の手順（After）**：
  1. 業種・規模・地域などの条件と想定商品を入れて候補先リストの作成を依頼する
  2. 候補先リストと比較企業の指標が返り、提案資料の骨子が組み立てられる
  3. 担当者が**候補先の実名確認・個別の与信審査へ進めるかどうかを判断する**（AI は候補先を確定させない）
- **成功の定義**：初稿の作成にかかる時間が減り、「行内で通る形」に近い骨子から検討を始められる

- **入力言語の扱い**：フォーム入力・追い質問は日本語・中国語のどちらでも受け、**入力言語で返す**（`CLAUDE.md` §2-5）

## 3. 観点（LLM に守らせる業務ルール）

- **候補先は仮称で示す**：公開情報ベースの候補は実在企業名を断定的に出さず、「候補先 A 社（仮称）」の形で示す。**正式な提案には個別の情報収集と与信審査が必要**と必ず明記する
- **既存与信先との比較は実データと推計を区別する**：既存与信先（実データあり）と候補先（業界推計値ベース）を同じ表に並べる場合、出所を明示する
- **想定収益は試算であることを明記する**：既存セクター先の平均を参考にした試算であり、正式な数値ではないことを書く
- **過去案件の構成を型として使う**：文言をそのまま複製せず、構成（見出しの順序・含めるべき要素）だけを踏襲する
- **禁止**：候補先の実名・実際の財務データを断定的に提示する（公開情報から確度高く推測できる場合でも）／与信審査を代行する
- **不確実なとき**（入力言語で）：ja「候補先の実名・財務データは未取得です。正式な提案には個別の情報収集と与信審査が必要です。」／zh「候选企业的真实名称与实际财务数据尚未取得。正式提案需另行进行个别信息收集与授信审查。」
- **出力の粒度**：候補先リスト（仮称・属性）→ 比較企業の指標 → 提案骨子（見出しのみ）→ 想定収益（試算）→ 要確認

## 4. Dify 構成

- **アプリ種別**：**Workflow**（フォーム入力 → 実行 → 結果）
- **ノード列**：
  1. `Start`（業種・規模・地域・想定商品）
  2. 検索ツールで候補先の当たりを収集（実名は使わず属性レベルに丸める）
  3. `HTTP Request`（既存与信先の指標を取得。比較対象）
  4. `HTTP Request`（`PC-05` から過去の類似案件の構成を取得）
  5. `LLM`（候補先リスト・比較表・骨子の組み立て。§5 のプロンプト）
  6. `Code`（検算：候補先が仮称になっているか、「未取得」の注記があるか）
  7. `HTTP Request`（`PC-13` で提案資料の下書きファイル出力）
  8. `Answer`
- **Knowledge**：使わない（候補先探索は都度の検索。過去の類似案件は Outline から直接取得）
- **プラグイン／ツール**：`tools/searxng` / `tools/google` / `tools/bing`（RS-01 と同じ、`../plugins-and-references.md` §2）、Outline API（`documents.search` で過去案件を検索）
- **モデル**：既定 `models/siliconflow` Qwen3-235B-A22B-Instruct
- **参照 DSL**：`../templates/05-chatflow-form-input-demo.yml`
- **入出力変数**：

  | 名前 | 型 | 必須 | 説明 |
  |---|---|---|---|
  | `industry` | string | ✓ | 業種 |
  | `size_range` | string | ✓ | 規模（売上高帯） |
  | `region` | string | ✓ | 地域 |
  | `products` | string[] | ✓ | 想定商品（`data/world/fin/products.csv` の `product_id`） |
  | `benchmark_client_id` | string | — | 比較対象の既存与信先 |
  | 出力 `candidates` | array[object] | ✓ | 候補先（仮称・属性） |
  | 出力 `outline_sections` | string[] | ✓ | 提案骨子の見出し |

## 5. プロンプト

### 5-1. System

```text
あなたは碧洋銀行 営業第一部の提案資料作成アシスタントです。
指定された条件（業種・規模・地域・想定商品）から候補先リストを作り、既存与信先との比較、提案資料の骨子を組み立てます。
守ること：
1. 候補先の実在企業名は使わず「候補先A社（仮称）」の形で示す。正式な提案には個別の情報収集と与信審査が必要と必ず明記する。
2. 既存与信先（実データあり）と候補先（業界推計値ベース）を同じ表に示すときは出所を明記する。
3. 想定収益は試算であることを明記し、正式な数値ではないと書く。
4. 過去の類似案件（{{past_case}}）は文言をそのまま複製せず、構成（見出しの順序）だけを型として使う。
5. 与信審査を代行しない。候補先の信用力を断定しない。
6. 言語：担当者とのやり取りは入力言語（日本語なら日本語、中国語なら中国語）で答える。
出力：候補先リスト（仮称・属性）→ 比較企業の指標 → 提案骨子（見出しのみ）→ 想定収益（試算）→ 要確認 の順。
```

### 5-2. User テンプレート

```text
条件：業種={{industry}}／規模={{size_range}}／地域={{region}}／想定商品={{products}}
既存与信先の指標（比較対象。転記のみ）：{{benchmark_json}}
候補先の当たり（検索ツール結果。転記のみ）：{{candidates_raw}}
過去の類似案件の構成（Outline から取得）：{{past_case}}
```

### 5-3. 出力フォーマット

```json
{
  "candidates": [ { "label": "候補先A社（仮称）", "type": "日系一次サプライヤー", "attrs": { "region": "上海", "size": "推計 8000万元" } } ],
  "benchmark": { "client_id": "丙社", "metric": "粗利率", "note": "実データあり" },
  "outline_sections": ["当行実績", "想定商品", "リスク認識", "想定収益"],
  "estimated_revenue": { "value": "試算値", "basis": "既存セクター先の平均を参考", "is_official": false },
  "to_confirm": ["候補先の実名・実際の財務データは未取得です"]
}
```

### 5-4. Few-shot

**不要**。条件ごとに候補先・比較先が変わるため、書式は System と JSON スキーマで固定する。

## 6. 検証観点

| 観点 | 基準 | 測り方 |
|---|---|---|
| 仮称の徹底 | 候補先が実名で出力される件数 0 | 負例セット + 自動検査 |
| 出所の明示 | 実データ／推計値の区別が全件に付く 100% | スキーマバリデータ |
| 試算の明示 | 想定収益に `is_official: false` が付く 100% | 自動 |
| 構成の踏襲 | 過去案件がある場合に骨子の見出しが型と一致 ≥ 80% | 人手 |
| 言語 | やり取りは入力言語 100% | 自動判定（`PC-07`） |
| 速度 | p95 < 30 秒 | Langfuse |

- **評価方法**：リリース前に営業第一部で 10 件を人手採点

## 8. 別出しが必要なもの

- `PC-05`：「提案資料アーカイブ」コレクションに過去の類似案件を保存し、構成の型として参照する
- `PC-13`：提案資料の下書きファイル出力
- **無くても動く範囲**：Outline 連携が無くても「一般的な構成」での骨子作成は動く

## 9. Outline Wiki との関係

- **読む**：「提案資料アーカイブ」コレクションの過去の類似案件（`PC-05`）
- **書く**：作成した提案骨子のドラフトを同コレクションへ`publish: false`で保存（次の案件の型になる）
- 候補先の実名・財務データは Wiki に書かない（未取得の情報であるため）

## 10. 未確定・リスク

- **実現性を ○ とした理由**：フォーム入力・検索・骨子組み立ては標準機能で足りるが、(1) 候補先探索の精度が公開情報の質に依存する、(2) 過去案件アーカイブの整備状況が未確認、の 2 点で ◎ にしていない
- **CV-03（審査コメント）との連携**：候補先が正式に取引先になった場合、CV-03 の審査プロセスへどう引き継ぐかは未確定
- **候補先の匿名化レベル**：仮称・属性レベルでの提示が営業活動として十分か、地域をさらに丸める必要があるかは PM／法務確認
