## 1. 業務シナリオ

- **いつ起きるか（トリガー）**：月次クローズ前に担当者が能動的に開く（`FA-02` の前提作業）。③業務フィードでは `routine`（月次クローズの一部）
- **登場人物**：事務統括部の主管（リコンシリエーションを行う側）、システム部（恒久対応を依頼する先）
- **いまの手順（Before）**：担当者が総勘定元帳（GL）と補助簿を手作業で突き合わせ、差異の原因を個別に調べる。同じ原因の差異が繰り返し発生していても、前月の処理内容を毎回思い出す必要がある
- **エージェント導入後の手順（After）**：
  1. 総勘定元帳と補助簿・基準記録をアップロードする
  2. 差異の一覧と、金額・日付・相手勘定から推定した原因が返る
  3. 前月に同じ差異が出ていた場合、そのときの処理も合わせて示される
  4. 担当者が**原因の確定と仕訳の要否を判断する**（AI は仕訳を計上しない）
- **成功の定義**：差異の洗い出しと原因推定にかかる時間が減り、恒久対応が未完了のまま再発している差異が可視化される

## 2. 想定インプット

| 種類 | 形式 | 言語 | 量・頻度 | 例 | 取得元 | 前処理 |
|---|---|---|---|---|---|---|
| 総勘定元帳 | xlsx | ja / zh | 月次 1 件 | 総勘定元帳_2026-08.xlsx | 会計システムのエクスポート | `tools/dify_extractor`（行レコード化） |
| 補助簿・基準記録 | xlsx | ja / zh | 月次 1〜複数件 | 補助簿_預金_貸出_2026-08.xlsx | 会計システムのエクスポート | 同上。勘定科目・日付・金額で GL と突合 |
| 前月のリコンシリエーション結果 | Markdown | ja | 月次 1 件 | 前月の差異一覧・処理内容 | Outline「GL リコン結果」コレクション（`PC-05`） | 今回の差異との突合（同一原因の再発検知） |

- **入力言語の扱い**：アップロードされる帳簿は日本語・中国語の科目名が混在しうる。**差異の説明は日本語**（事務統括部の報告が日本語ベースであるため。台本参照）。担当者とのやり取りは入力言語に従う（`CLAUDE.md` §2-5）
- **入力の欠け・曖昧さ**：前月データが Outline に無い（初回）場合は「前月との比較なし」と明示する。原因が特定できない差異は「原因不明」とし、金額の多寡にかかわらず推測で埋めない

## 3. 観点（LLM に守らせる業務ルール）

- **差異の合計・件数は Code の計算結果を転記する**：GL と補助簿の合計値・差異件数を LLM が計算しない
- **原因推定は「推定」と明示する**：金額・日付・相手勘定から推定できる原因（決済日と受渡日の計上基準の違い 等）は「推定原因」として書き、確定原因として断定しない
- **前月との同一性を機械的に判定する**：勘定科目・原因の分類が前月と一致する場合のみ「再発」と表現する。似ているが違う原因を再発と混同しない
- **恒久対応の進捗を追跡する**：前月に恒久対応（システム部への依頼等）が記録されていれば、その進捗確認を促す一文を添える
- **禁止**：仕訳の計上・確定をする（「暫定仕訳を計上済み」等の記述は `FA-02` からの転記のみで、本サービス自体は仕訳を作らない）／原因不明の差異を推測で確定原因にする
- **不確実なとき**（入力言語で）：ja「この差異の原因は特定できませんでした。金額・日付・相手勘定を確認してください。」／zh「无法确定该差异的原因，请确认金额、日期与对方科目。」
- **出力の粒度**：対象科目の残高 → 差異一覧 → 推定原因 → 前月との比較（再発の有無）→ 確定前の確認（原因不明な差異の扱い）

## 4. Dify 構成

- **アプリ種別**：**Workflow**（ファイルアップロード → 抽出 → 突合 → 結果）
- **ノード列**：
  1. `Start`（総勘定元帳 xlsx、補助簿・基準記録 xlsx。複数可）
  2. `tools/dify_extractor`（行レコード化）
  3. `Code`（GL と補助簿の勘定科目・金額・日付での突合。差異の機械的検出。**唯一の数値計算の出所**）
  4. `HTTP Request`（`PC-05` から前月のリコンシリエーション結果を取得）
  5. `Code`（前月結果との突合。同一勘定科目・同一原因分類なら「再発」フラグ）
  6. `LLM`（差異ごとの推定原因・前月比較の説明。§5 のプロンプト）
  7. `HTTP Request`（`PC-05` に今回の結果を保存。次回比較用）
  8. `Answer`
- **Knowledge**：使わない
- **プラグイン／ツール**：`tools/dify_extractor`（`../plugins-and-references.md` §1）、Outline API（読み書き）
- **モデル**：既定 `models/siliconflow` Qwen3-235B-A22B-Instruct（説明文の生成のみ。計算は Code）
- **参照 DSL**：`../templates/04-trilingual-consistency-checker.yml`（行単位の突合・判定表の型）
- **入出力変数**：

  | 名前 | 型 | 必須 | 説明 |
  |---|---|---|---|
  | `period` | string | ✓ | 対象月（`YYYY-MM`） |
  | `gl_file` | file | ✓ | 総勘定元帳 |
  | `subledger_files` | file[] | ✓ | 補助簿・基準記録 |
  | 出力 `balances` | object | ✓ | 対象科目の残高（GL・補助簿） |
  | 出力 `differences` | array[object] | ✓ | 差異一覧（推定原因・再発フラグ） |

## 5. プロンプト

### 5-1. System

```text
あなたは碧洋銀行 事務統括部の GL リコンシリエーション担当です。
突合済みの差異データ（{{diff_json}}）と前月のリコンシリエーション結果（{{prev_result}}）から、
差異の状況を日本語で説明します。
守ること：
1. 残高・差異の件数・金額は与えられた {{diff_json}} をそのまま使う。自分で計算しない。
2. 原因は金額・日付・相手勘定から「推定原因」として書き、確定原因と断定しない。
3. 前月と同一の勘定科目・原因分類のときだけ「再発」と表現する。異なる場合は再発と書かない。
4. 前月に恒久対応が記録されている場合は、その進捗確認を促す一文を添える。
5. 仕訳の計上・確定はしない。
6. 原因が特定できない差異は「原因不明」と書き、推測で確定原因にしない。
7. 言語：説明は日本語。担当者とのやり取りは入力言語（日本語なら日本語、中国語なら中国語）で答える。
出力：対象科目の残高 → 差異一覧 → 推定原因 → 前月との比較（再発の有無）→ 確定前の確認 の順。
```

### 5-2. User テンプレート

```text
対象月={{period}}
残高・差異（Code 転記のみ）：{{diff_json}}
前月のリコンシリエーション結果（Outline から取得。無ければ空）：{{prev_result}}
```

```json

    { "item": "クロスボーダー人民元送金 3件", "amount": "未計上", "estimated_cause": "区分コード欄が旧様式のため未計上（推定）", "recurred": true, "prev_handling": "前月は手作業で追記して対応。恒久対応（システム部への様式登録）は未完了" },
    { "item": "端数調整", "amount": "800元", "estimated_cause": "原因不明", "recurred": false }
  ],
  "to_confirm": ["原因不明の端数調整800元は月次クローズまでに調査するか、僅少額として繰り越すか判断してください"]

```

### 5-4. Few-shot

**不要**。差異は月ごとの実データに依存するため、書式は System と JSON スキーマで固定する。

## 6. 検証観点

| 観点 | 基準 | 測り方 |
|---|---|---|
| 数値の非捏造 | 残高・差異の金額が Code 出力と完全一致 100% | 自動突合 |
| 推定の明示 | 原因説明に「推定」の語が付く 100% | 自動（キーワード検査） |
| 再発判定の正確性 | 前月と同一原因分類のみ「再発」 100% | 自動突合 |
| 仕訳の非計上 | 「仕訳を計上した」等の断定表現の出現 0 | 禁止語検査 |
| 言語 | 説明は日本語、やり取りは入力言語 100% | 自動判定（`PC-07`） |
| 拒否 | 原因不明の明示 100% | 自動 |
| 速度 | p95 < 30 秒 | Langfuse |

- **評価方法**：リリース前に事務統括部で 15 件を人手採点

## 8. 別出しが必要なもの

- `PC-05`：「GL リコン結果」コレクションに前月結果を保存し、次回はここを読んで再発判定を行う
- `PC-03`：総勘定元帳・補助簿の抽出
- **無くても動く範囲**：Outline 連携が無くても今回の差異一覧・推定原因は動く（再発判定ができないだけ）

## 9. Outline Wiki との関係

- **読む**：「GL リコン結果」コレクションの前月結果（`PC-05`）
- **書く**：今回の差異一覧・推定原因をドラフトとして保存（`publish: false`）。確定は事務統括部が行う
- 会計処理そのもの（仕訳の実行）は書かない

## 10. 未確定・リスク

- **実現性を ○ とした理由**：ファイルアップロード・突合・説明生成は標準機能で足りるが、(1) GL・補助簿のフォーマットが会計システムによって異なる可能性、(2) 前月結果の保存粒度（勘定科目単位か差異単位か）が未確定、の 2 点で ◎ にしていない
- **`FA-02`（月次クローズ）との連携**：本サービスの差異一覧・原因不明の項目は `FA-02` のチェックリストの入力になる（台本参照）。連携経路（自動受け渡しか手動転記か）は次の設計で詰める
- **恒久対応の追跡**：「システム部への様式登録依頼」の進捗そのものは本サービスの範囲外。進捗管理は `GN-06`（頼まれ事の追跡）に票として起票する運用を想定するが、本 PR では自動連携しない
