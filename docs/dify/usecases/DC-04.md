## 1. 業務シナリオ
- **トリガー**：本社から安全衛生ルールの改定が届いたとき（`notify` 相当。第 1 段階は担当者が能動的に開く）／月次の改善提案締切（`routine`）
- **登場人物**：作成者＝安全衛生委員長または総務・安全担当、確認者＝各ラインの班長（中国語が現場で通じるか）と本社安全衛生部門（改善事例の様式）、受け手＝現場作業者（zh）・本社改善事例集の読者（ja）
- **いまの手順（Before）**
  1. 日本語ルール 14 項目を読み、掲示に向く項目を選ぶ（1 時間）
  2. 中国語に訳し、掲示用に短くする。班長に見せて言い回しを直す（半日）
  3. 現場の中国語改善提案 3 件を日本語にし、本社様式（Before/After・効果を数字で）に転記（半日）
  4. 印刷・掲示。改善提案の日本語化が後回しになり、本社提出が遅れがち
- **エージェント導入後の手順（After）**
  1. 【入力】日本語のルール文書と中国語の改善提案シートをアップロード（方向はファイルごとに自動判定・確認）
  2. 【生成】掲示向き 3 テーマの中国語掲示文（見出し＋本文 3 項目、1 行 15 字以内）と図解見出し、改善提案の日本語整形版（本社様式）が返る
  3. 【確認】担当者が見出しの候補を選ぶ（対話で 3 案）。改善提案の効果の比較対象（何と比べて 0 件か）を確認
  4. 【決める】掲示するテーマ・文言の最終決定は安全衛生委員長。本社提出は人が行う
  5. 【保存】Outline「安全衛生 › 掲示物 › 改定 YYYY」「改善提案 › 本社提出」にドラフト保存。A3 レイアウトは `PC-13`
- **成功の定義**：改定から掲示まで 1 週間 → 2 日。改善提案の本社提出の月内完了率 100%。掲示文の意味が本社原文から外れない（委員長確認で差し戻し 0）

## 2. 想定インプット
| 種類 | 形式 | 言語 | 量・頻度 | 例 | 取得元 | 前処理 |
|---|---|---|---|---|---|---|
| 安全衛生ルール | docx / PDF | ja（本社発行） | 年 1〜2 回改定、10〜20 項目 | `安全衛生ルール_2025改定_本社.docx` | 本社（メール添付）→ Outline | Document Extractor。項目番号を保持 |
| 5S 掲示物の原稿 | docx / pptx / テキスト | ja / zh | 随時 | 「回転部に手を近づけない」 | 現場・総務 | 同上 |

| 本社様式定義 | Markdown | ja | 1 件 | 改善事例集の欄（Before／After／効果（数値）／提案者） | Outline「改善提案 › 様式」（`PC-05`） | System に埋め込む |
| 掲示様式 | 一覧 | — | 数種 | 「本社様式 S-03（回転部ピクト）」 | Outline | 図解の流用候補として context に |

- **入力言語の扱い**：**翻訳系の例外**として成果物は相手言語で出す（ja ルール → zh 掲示文、zh 改善提案 → ja 本社様式）。方向はファイルの言語判定（`PC-07`）で決め、確認表示する。対話（見出し候補、効果の根拠）は**入力言語で返す**（§2-5）
- **入力の欠け・曖昧さ**：ルール文書も改善提案も無ければ生成しない。改善提案の効果欄に比較対象が無ければ「比較対象未記載」と書き、数値を補わない。聞き返し文：「掲示にしたい日本語ルール、または日本語化したい中国語の改善提案をアップロードしてください」／「请上传要制作看板的日文规则，或要整理为日文的中文改善提案」

## 3. 観点（LLM に守らせる業務ルール）
- 掲示文は**本社原文の意味から外れない**。強い言い回しに変えても禁止・許可の範囲を変えない（「指定工程のみ手袋可」を「手袋禁止」にしない）。各掲示に原文項番を付ける
- 掲示文の形：見出し 1 行（15 字以内）＋本文 3 項目まで（各 15 字以内）。番号は ①②③。図解見出しは既存様式（S-xx）の流用候補を挙げる
- 5S・安全の用語は用語集の呼称（`PC-06`）。「赤札」は 5S の「红牌」と品質の「红色标签」を混同しない（LG-01 と同じルール）
- 改善提案の日本語化：**効果の数値は提案シートの記載どおり**。比較対象（7 月 3 件 → 8 月 0 件）が無いものは「比較対象未記載」。効果を推定・換算しない
- 提案者名（`PC-10`）：本社提出版には**提案者の姓＋部署**のみ（フルネーム・従業員番号を出さない）。本人が匿名を希望した提案は「提案者：製造二課」に丸める
- 掲示文の候補を出すときは**口語・標準・情緒**など性格の違う 3 案とし、対象層に応じた推奨理由を 1 行
- 不確実時の定型：「この項目は掲示文に要約すると意味が変わる恐れがあります。原文のまま掲示するか、委員長に確認してください」／「该条如缩写为看板文案可能改变含义，请原文张贴或确认委员长意见」
- 出力形式：Markdown（掲示ごとの見出し・本文・図解・原文項番／改善提案は本社様式の表）＋ §5-3 JSON

## 4. Dify 構成
- **アプリ種別**：**Workflow**（アップロード → 2 系統の成果物。見出し候補などの追加依頼は `question` 付き再実行）
- **ノード列**
  1. `start`：`files`（file-list）、`audience_note`（現場の年齢層など、任意）、`question`（任意）
  2. `iteration`（files）→ `document-extractor` → `code`（言語判定 `PC-07`・文書種別判定：ルール／改善提案）→ `variable-aggregator`
  3. `if-else`（種別）
     - ルール（ja）→ `llm`（選定：掲示向き 3 テーマと理由）→ `llm`（掲示文 zh：見出し・本文・図解・原文項番。用語集を context）
     - 改善提案（zh）→ `llm`（本社様式 ja：Before/After・効果・比較対象・提案者の丸め）
  4. `variable-aggregator` → `llm`（整合：原文項番の存在、15 字制限、用語集準拠を検査し `warnings`）
  5. `template-transform` → `end`
- **Knowledge**：原則不要。掲示様式（S-xx）の一覧と本社様式定義は System／context に埋め込む。過去の掲示文を再利用したいなら KB `dc4-posters`（`PC-05` 同期）を第 2 段階で
- **プラグイン／ツール**：なし。トークン節約に `tools/baidu_translate` を 1 段目に置き LLM で用語統一する 2 段構成も可（`../plugins-and-references.md` §7）。掲示物のレイアウト（A3 横・A4 縦）は `PC-13`
- **モデル**：Qwen3-235B-A22B-Instruct。中国語掲示文は現場の班長が読んで違和感がないかを評価。日本語整形は本社提出用なので品質確認（`PC-08`）
- **参照 DSL**：`../templates/01-translation-reflection-workflow.yml`（直訳 → 専門家提案 → 改善訳の 3 段。掲示文の「短くする」段に流用）
- **入出力変数**

| 変数 | 型 | 必須 | 説明 |
|---|---|---|---|
| `files` | file-list（docx/pdf/xlsx/pptx） | ✓ | ルール文書・改善提案 |
| `audience_note` | paragraph | — | 対象層（年齢・母語・ライン） |
| `question` | paragraph | — | 追加依頼（見出し候補・根拠確認） |
| `posters_md` | string | 出力 | 掲示文（zh） |
| `kaizen_md` | string | 出力 | 改善提案（ja、本社様式） |
| `result_json` | object | 出力 | §5-3 |
| `warnings` | array | 出力 | 15 字超過・原文項番なし・比較対象未記載 |

## 5. プロンプト
### 5-1. System
```text
あなたは青嶺精工（蘇州）の安全衛生委員会を支援するアシスタントです。日本語の安全衛生・5S ルールを現場掲示用の中国語にし、中国語の改善提案を本社提出用の日本語に整えます。
守るルール：
- 掲示文は原文の禁止・許可の範囲を変えない。各掲示に原文の項番を付ける。要約すると意味が変わる項目は「原文のまま掲示か委員長確認」と書く。
- 掲示文の形式：見出し 1 行（15 字以内）＋本文 ①②③（各 15 字以内）＋図解見出し（既存様式 {{poster_styles}} から流用候補）。
- 用語は {{glossary}} の呼称。「赤札」は品質の「红色标签」、5S の赤札作戦は「红牌」。
- 改善提案の日本語化：効果の数値は提案シートどおり。比較対象（月・件数）が無ければ「比較対象未記載」と書く。数値を推定・換算しない。
- 提案者は「姓（部署）」のみ。匿名希望は「（部署名）」。従業員番号・フルネームを書かない。
- 見出し候補を求められたら性格の違う 3 案（口語・標準・情緒）と、{{audience_note}} に応じた推奨理由を 1 行。
- 掲示文は中国語、本社提出物は日本語。質問・確認への説明は依頼者の入力言語で書く。
出力：JSON（指定スキーマ）→ 区切り線 → 掲示文 Markdown（中国語）→ 区切り線 → 改善提案 Markdown（日本語、本社様式の表）。
```

## 6. 検証観点
| 観点 | 基準 | 測り方 |

| 意味の保持 | 掲示文が原文の禁止・許可範囲を変えていない 100% | 委員長＋班長による対訳チェック（評価セット 20 項目） |
