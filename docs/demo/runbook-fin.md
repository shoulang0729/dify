## 4. うまくいかなかったときの逃げ道

**実機を操作していないため、`dify/KNOWN_ISSUES.md` の `DI-xxx`（Dify Cloud への投入・テストで観測された不具合）に
対応する実行時障害はここには無い。** 起こりうるのはモック画面側の一般的なトラブルだけなので、それに絞って記す。

| 症状 | 原因 | その場の言い方・対応 |
|---|---|---|
| `catalog.html` が真っ白・崩れる | ブラウザのキャッシュ、または `file://` での相対パス解決の問題 | リロード、または別ブラウザ（シークレットウィンドウ）で開き直す |
| 「はじめる」を押しても `demo` 画面にならず従来の `chat` 画面になる | `SCENARIOS` にその管理番号の台本が無い（本台本の 5 件は全件登録済みのため通常は起きない） | 起きた場合はサービス選択を誤っている可能性が高い。分類・管理番号を確認し直す |
| 言語切替後に会話が消える／表示がおかしい | `state.log`（消費済みターン数）の再描画で表示がずれることがある | 「はじめる」からもう一度再生し直す |
| 顧客から「これは本当に動いているのか」と聞かれる | モックは LLM に接続していないダミー応答（設計どおり） | 正直に「これは画面上の台本を再生したものです。実機（Dify Cloud）はまだ無く、W4 で用意する計画です」と答える（§0-2 の非対称をそのまま説明する） |
| 「入力サンプルを見せてほしい」と言われる | `dify/samples/{KN-06,KN-08,DC-09,RS-01,RS-03}/` は本ドキュメント作成時点で未整備 | 「入力サンプルは整備中です。本日はこの台本の読み上げ文で代替しています」と説明する |

## 5. 片付け

- **会話ログの扱い**：モックの会話状態（`state.log`）はブラウザのメモリ上だけで、ページを閉じる／リロードすると消える。`localStorage` に保存されるのは `mock.lang`／`mock.theme`／`mock.fav` の 3 キーだけで、会話内容は保存されない
- **顧客に URL を渡すかの判断基準**：モックの Pages URL（`https://shoulang0729.github.io/dify/`）は架空データのみのデモ画面であり、顧客に渡してよい。ただし**実機（Dify Cloud）の URL は存在しないため、そもそも渡しようがない**。将来 W4 で実機ができた場合は、`runbook-mfg.md` §5 と同じ基準（`CLAUDE.md` §2-10：架空データだけの環境か）で判断する
- 顧客からの追加質問で即答できないものは `faq.md` を見る、それでも無ければ持ち帰りとする
