設計書 `docs/handoff/2026-09-09-demo-assets.md` D7・§7（Issue #205 PR-7）に基づく司会台本です。
Dify Cloud（`cloud-master`）で動く実機 12 本を、担当者が読み上げながら進行するための手順書であり、
モックの `SCENARIOS`（画面に出る会話データ）ではありません。混同しないよう、次の表で違いを確認してから使ってください。

## 0. このデモの前提

### 0-1. モックの `SCENARIOS` との違い（境界の表）

| | モックの `SCENARIOS`（`mock/js/data/scenarios/**`） | この台本（`docs/demo/runbook-mfg.md`） |
|---|---|---|

**この台本が動かす画面は、モックの catalog.html ではありません。** Dify Cloud の実アプリ（Studio のプレビュー／チャット枠）を直接操作します。

### 0-2. 所要時間・参加者・環境

- **所要時間**：本編（§3 の 12 ターン合計）は目安 **約 24 分**（各ターンの内訳は §3 参照。20 秒の読み上げ＋実測の応答待ち＋40 秒の説明というモデルで見積もった**想定**で、実測の合計ではない）。導入・まとめ（§1・§5）を含めた正味の所要は**未計測**。当日は 12 本すべてを通しで行わず、聞き手の業種・関心に応じて抜粋してよい
- **参加者**：司会（本台本の読み上げ担当）1 名、技術バックアップ（§4 の逃げ道と `dify/KNOWN_ISSUES.md` を手元に置く担当）1 名、顧客側の参加者
- **使う環境**：`cloud-master`（架空世界 `data/world/mfg/` のデータしか入っていない環境）**のみ**。他の環境（`inhouse`／`customer-a` 等）は使わない
- **見せる URL の範囲**：`mock/js/data/live.js`（`LIVE`）は本ドキュメント作成時点で**まだ空**（Issue #124 の UI は入ったが、公開 Web アプリ URL の入手経路が未確認）。したがって当日は**顧客に URL を渡さず**、司会側の画面共有で Dify Cloud Studio のプレビュー／チャット枠を直接操作して見せる（`dify/DEPLOY.md` §9 の「画面で見せるだけ」と同じ考え方）
- **禁止事項**：顧客の実データを入力しない・実名を口にしない（`CLAUDE.md` §2-10）。投入するのは `dify/samples/` の架空サンプルだけ
- **工数削減の言い方**：削減率・削減時間は口頭でも資料でも示さない。「どれだけ工数が減るか」と聞かれたら `faq.md` Q33 の言い方に揃え、示せるのは AI 側の実測応答時間と、対象業務の所要時間の**想定**（未実測）であることをそのまま伝える

## 4. うまくいかなかったときの逃げ道

| 症状 | 原因 | その場の言い方 | 参照（`dify/KNOWN_ISSUES.md`） |
|---|---|---|---|
| KN-01 の検索結果が的外れ／古い版の条件を引用する | KB のチャンク分割が条件表・箇条書きを分断することがある（未対処） | 「検索結果の精度は文書の区切り方に依存します。ここは継続的に改善している項目です」 | `DI-006`（open） |
| KB 付き 4 本（KN-01・KN-02・KN-03・GN-01）の公開画面が開けない／「Rerank モデル は必須です」で止まる | `dataset_ids` を焼き込んだ build 版の再インポート時に KB 紐づけの副作用が起きず、公開チェックリストで止まる | 「こちらは社内のワークスペースから直接お見せします」と言って Studio のプレビュー画面（非公開の下書き相当）で続行する | `DI-033`（open） |
| DC-01 の安全ケースで社外秘の値がそのまま出る／入力に無い参照番号を作る | ルールの優先順位の解釈が揺れることがある（未対処） | 「最終的な出力は必ず人が確認してから使う運用にしています」 | `DI-009`（open） |
| LG-01／LG-04 で解説・用語対応表・注記だけ日本語のまま残る（訳文本体・件名・本文は正しく相手言語） | セクションごとに回答言語が変わる構成で、共通ルールがどのセクションの言語かを解決しきれていない | 「相手にお送りする本文・件名は正しく相手言語で出ています。社内向けの解説欄は継続的に改善している項目です」 | `DI-026`／`DI-031`（いずれも open） |
| DC-04 の注記（必須）が依頼者の入力言語と異なる | 同上（セクション別の回答言語の扱い） | 「掲示文本体は正しい言語で出ています。注記の言語は継続対応中です」 | `DI-027`（open） |
| KN-03 の見出し語の一部だけ日本語が残る（例：「拠」の 1 字） | 対応語の置き換えが本文には効くが見出し語に効き切らないことがある | 「本文の専門用語は正しく訳されています。見出し語の細部は継続対応中です」 | `DI-032`（open） |
| GN-05 で日付・通貨の書き方が原文と変わる（例：ISO 日付が現地表記に、`RMB` が「人民元」に） | 「地の文は回答言語で書く」ルールが日付・通貨コードの転記ルールより強く効くことがある | 「数値そのものは正しく、表記の形式だけの差です」 | `DI-030`（open） |
| 応答が極端に遅い（1 分を大きく超える）・タイムアウトする | 過去に LLM の思考（reasoning）が長引き Cloud 前段の 120 秒タイムアウトを超えたことがある（現在は思考量の制御で解消済み） | 「もう一度同じ質問を送ってみます」。それでも遅ければ次のターンへ進み、あとで再挑戦する | `DI-010`（fixed。再発時の参考） |

**逃げ道が効かない場合**：§1 のフォールバックに戻り、当該アプリのターンをモックの demo テンプレに切り替える。

## 5. 片付け

- **会話ログの扱い**：デモ中にチャットへ入力した内容・出力は Dify Cloud 側のログに残る。架空サンプルのみを使っていれば問題は無いが、参加者の即興の質問（実データを含む可能性）を入力しないよう当日改めて注意する
- **顧客に URL を渡すかの判断基準**：`CLAUDE.md` §2-10 のとおり、**架空データだけの環境（`cloud-master`）である**ことを確認できていれば公開 URL を渡してよい。ただし本ドキュメント作成時点で `LIVE`（`mock/js/data/live.js`）は空であり、渡せる URL がそもそも無い。`LIVE` に URL が登録された後、あらためて環境台帳（`dify/env/README.md`）の確認状態と対で判断する
- 顧客からの追加質問で即答できないものは `faq.md` を見る、それでも無ければ持ち帰りとする
