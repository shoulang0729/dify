# SwingAnalist 仕様書

- 作成日: 2026-06-12
- ステータス: **設計確定（実装前）**
- 想定 DSL: `apps/swing-analist.yml`（雛形は `apps/multi-model-compare.yml` / `version: 0.6.0` を使用すること — CLAUDE.md ルール1）
- 表記: アプリ名は発案時の表記「SwingAnalist」を維持する（英語綴りとしては Analyst）。

## 1. 概要

ゴルフスイング動画（正面 or 後方）をアップロードすると、

1. スイング理論の標準ポジション **P1〜P10** の連続静止画を自動で切り出し、
2. クラブ角度・体の角度などを**注釈入り画像**でハイライトし、
3. 弱点を診断して**改善ドリルを提案**し、
4. 撮影日付つきで **Notion データベースに記録**して**定点観測（前回比較）**を可能にする

Dify アプリ（advanced-chat）＋外部フレーム抽出 API ＋ Notion の構成。

## 2. 確定した設計判断

| # | 論点 | 決定 | 理由・補足 |
|---|------|------|-----------|
| 1 | 動画→静止画の切り出し | **最初から外部 API を構築**（Cloud Run 等に ffmpeg + MediaPipe） | 動画1本投げるだけの UX と、切り出し位置の一貫性（定点観測の比較精度）を最優先。姿勢推定から角度の実測値も取れる |
| 2 | 角度のハイライト | **画像生成モデルで注釈画像を生成** | 切り出した静止画にライン・角度を描き込んだ画像を返す。精密描画（OpenCV）は将来の改善候補 |
| 3 | 記録・定点観測の保存先 | **Notion データベース** | HTTP ノードで書き込み・読み出し。過去レコードを取得して前回比コメントを生成 |
| 4 | 分析フレームワーク | **P1〜P10 システム** | プロのレッスンで標準的な10ポジション分割 |
| 5 | 撮影方向（正面/後方） | **Vision LLM が自動判定** | ユーザー入力不要。判定結果はビュー別チェック項目の切替と Notion 記録に使用 |
| 6 | ドリル提案の知識源 | **まず LLM 内蔵知識 → 後で RAG 化** | v1 は内蔵知識で運用し、良かった提案を `knowledge/` に蓄積して Dify ナレッジへ昇格 |
| 7 | 利用者 | **家族・友人と共用** | 開始時にプレイヤー名を入力。Notion DB にプレイヤー列を持ちフィルタ可能にする |

## 3. 全体アーキテクチャ

```
[ユーザー]
   │ ①動画アップ + プレイヤー名（+任意で撮影日）
   ▼
[Dify advanced-chat]
   │ ②HTTPノード: 動画URLを送信
   ▼
[フレーム抽出API (Cloud Run)]  ffmpeg + MediaPipe
   │ ③P1〜P10のキーフレーム検出 → 静止画10枚 + 姿勢の実測角度(JSON)
   ▼
[Dify]
   ├ ④Vision LLM: ビュー自動判定(正面/後方) + P1〜P10診断
   ├ ⑤画像生成モデル: 重要ポジションの注釈画像を生成
   ├ ⑥LLM: 弱点サマリ + 改善ドリル提案
   ├ ⑦HTTPノード: Notion過去レコード取得 → 前回比コメント生成
   ├ ⑧HTTPノード: Notionへ今回の分析を記録
   ▼
[Answer] 注釈画像 + 診断 + ドリル + 前回比
```

## 4. コンポーネント仕様

### 4.1 フレーム抽出 API（外部・新規構築）

- **ホスティング**: Cloud Run（従量課金・ほぼ無料枠内を想定）。リージョンは実装時に決定。
- **技術スタック**: Python + ffmpeg（フレーム展開）+ MediaPipe Pose（姿勢推定）
- **エンドポイント（案）**: `POST /extract`
  - リクエスト: `{ "video_url": "<DifyのファイルURL>", "view_hint": "auto" }`
  - レスポンス:
    ```json
    {
      "view": "front | rear | unknown",
      "frames": [
        { "position": "P1", "image_url": "...", "timestamp_ms": 0,
          "metrics": { "shaft_angle_deg": 0, "spine_tilt_deg": 0, "shoulder_turn_deg": 0 } }
      ],
      "fps": 240, "duration_ms": 0
    }
    ```
- **キーフレーム検出ロジック（初期案）**:
  - 手首ランドマークの速度・高さ、クラブ（手首延長線）の角度変化から P1（静止）/P4（トップ=手首速度ゼロクロス）/P7（インパクト=最下点+最大速度）を先に確定し、P2/P3/P5/P6/P8〜P10 はその間を角度基準で補間検出。
  - **P2/P3/P5 など中間ポジションの判定精度が最大の技術リスク**。M1（フェーズ計画参照）で実動画により検証する。
- **認証**: API キー方式。キーは Dify の `environment_variables`（secret 型）に保持。**リポジトリにはコミットしない**（CLAUDE.md ルール2）。
- **要検証**: Dify Cloud のアップロードファイル URL（署名付き）を外部 API から取得できるか。不可の場合は Dify から base64 で POST する方式に切り替える（動画サイズ上限に注意）。

### 4.2 Dify アプリ（advanced-chat）

- **mode**: `advanced-chat`、DSL `version: 0.6.0`（既存 export 準拠）
- **file_upload**: video を許可（`.MP4` `.MOV`、上限 100MB、1ファイル）
- **開始時入力**:
  - `player_name`（テキスト・必須）— 共用前提
  - 撮影日: ユーザーが発話で指定（例「6/10に撮った」）すれば LLM が抽出、指定なしは**実行日を撮影日とみなす**
- **ノードフロー**: 上記アーキテクチャ図 ②〜⑧ の順。HTTP ノードのタイムアウトは最大値に設定（動画処理は数十秒かかる想定）。
- **モデル**: OpenRouter（OpenAI-Compatible）経由。
  - 診断（Vision）: Gemini 2.5 Pro クラスの vision 対応モデル
  - 注釈画像生成: Gemini 系画像生成モデル
  - ※モデルスラッグは実装時に openrouter.ai/models の正確な表記を確認すること（既存 DSL の注意書きと同じ運用）

### 4.3 注釈画像生成

- 対象: 全10枚ではなく、**診断で弱点と判定されたポジション（最大3枚）** に絞る（生成コスト・実行時間対策）。
- 描き込む内容: シャフトライン（理想 vs 実際）、前傾角、肩・腰の回転ライン、頭の位置基準線。
- 画像生成モデルの描画精度は不安定なため、**数値の正は API の `metrics`（姿勢推定の実測値）** とし、注釈画像は「見て分かる補助」と位置づける。

### 4.4 Notion データベース スキーマ

| プロパティ | 型 | 内容 |
|-----------|----|------|
| タイトル | title | `{player} {撮影日} {ビュー}` |
| 撮影日 | date | 定点観測の主キー的役割 |
| プレイヤー | select | 家族・友人の名前 |
| ビュー | select | 正面 / 後方 |
| クラブ | select | ドライバー / アイアン等（発話から抽出、不明なら未設定） |
| 総合スコア | number | 100点満点の総合評価（LLM 採点） |
| 弱点タグ | multi_select | 例: オーバースイング, アーリーエクステンション, スウェー |
| 主要数値 | rich_text | P4肩回転角、P7シャフト角などの実測値 JSON/要約 |
| 診断サマリ | rich_text | 弱点と根拠の要約 |
| 提案ドリル | rich_text | 提案したドリル一覧 |
| 注釈画像 | files/url | 生成した注釈画像へのリンク |

- Notion インテグレーショントークンも `environment_variables`（secret 型）で保持。
- DB の `database_id` はインスタンス固有 → DSL 内に直書きする場合は移行時に貼り替え（既存 `dataset_ids` と同じ注意）。

### 4.5 定点観測

- 分析の最後に Notion から**同一プレイヤーの直近レコード（最大3件）**を取得し、
  - 弱点タグの増減（解消した弱点 / 新たな弱点）
  - 主要数値の推移（例: 肩回転 80°→ 88°）
  - 前回提案ドリルへの言及（「前回の○○ドリルの効果が出ています」）
  を含む**前回比コメント**を生成する。
- 初回（過去レコードなし）はベースライン登録である旨を伝える。

## 5. 分析仕様（P1〜P10 チェック項目）

ビューは Vision LLM が自動判定し、該当列の項目を適用する。

| Pos | 名称 | 正面ビューの主チェック | 後方ビューの主チェック |
|-----|------|----------------------|----------------------|
| P1 | アドレス | ボール位置、体重配分、スタンス幅 | 前傾角、シャフトと前腕の角度、ボールとの距離 |
| P2 | シャフト水平(バック) | 体のスウェー | シャフトがつま先ラインと平行か、フェース向き |
| P3 | リード腕水平 | 左腕の高さ、頭の移動 | シャフトプレーン、右肘の畳み |
| P4 | トップ | 肩の回転量、リバースピボット | シャフトのクロス/レイドオフ、オーバースイング |
| P5 | リード腕水平(ダウン) | 下半身先行の有無 | シャフトの寝かし/立ち（シャローイング） |
| P6 | シャフト水平(ダウン) | 腰の開き | クラブが飛球線と平行・プレーン上か |
| P7 | インパクト | 頭の位置、体重移動、ハンドファースト | 前傾維持（アーリーエクステンション） |
| P8 | シャフト水平(フォロー) | 伸び上がり | 振り抜き方向（インサイドアウト/アウトサイドイン） |
| P9 | トレイル腕水平 | チキンウィング | 体の回転との同調 |
| P10 | フィニッシュ | バランス、体重の左足乗り | 回転の完了度 |

## 6. ドリル提案（内蔵知識 → RAG 化の運用ループ）

- **v1 運用**: LLM 内蔵知識で「弱点タグごとに 1〜2 個、自宅/練習場で可能なドリル」を提案。
- **RAG 化への蓄積ループ**:
  1. 実際に効果があったドリル・良かった提案を `knowledge/swing-drills.md`（弱点タグ × ドリル対応表）に追記していく
  2. ある程度たまったら Dify ナレッジに登録し、ドリル提案ノードを RAG 参照に切替
  3. 切替後は提案の一貫性が上がり、自分たち向けにカスタマイズされたドリル集に育つ

## 7. セキュリティ・運用ルール

- フレーム抽出 API キー / Notion トークンは **Dify の environment_variables（secret）のみ**に置く。DSL export に secret 値は含まれない前提だが、**コミット前に DSL 内へ生キーが混入していないか必ず確認**する。
- DSL ファイルは `apps/swing-analist.yml`。変更は `scripts/ship.sh` で PR 経由マージ（CLAUDE.md ルール5）。

## 8. 制約・リスク

| リスク | 影響 | 対策 |
|--------|------|------|
| 中間ポジション（P2/P3/P5等）の自動検出精度 | 切り出し画像がズレ、診断・定点比較の質が落ちる | M1 で実動画検証。精度が出ない Pos は近傍3フレームを返して LLM に最適フレームを選ばせる代替案 |
| Dify Cloud のファイル URL を外部 API へ渡せない可能性 | アーキテクチャの根幹に関わる | M1 で最初に検証。不可なら base64 POST へ切替 |
| Dify Cloud Sandbox の実行時間・回数制限 | 動画処理＋画像生成で全体が長時間化 | 注釈画像を最大3枚に制限。恒久対処は v2 セルフホスト（CLAUDE.md ルール6） |
| 画像生成モデルの注釈精度が不安定 | ハイライトの線がズレる | 数値の正は MediaPipe 実測値とし、画像は補助。将来 OpenCV 描画に置換可能な構成にする |
| Cloud Run のコールドスタート | 初回リクエストが遅い | min-instances=0 で運用しタイムアウトを長めに。気になれば min-instances=1 |

## 9. 実装フェーズ計画

| フェーズ | 内容 | 完了条件 |
|---------|------|---------|
| **M1** | フレーム抽出 API プロトタイプ（ローカル→Cloud Run）。Dify ファイル URL 受け渡し検証 | 手持ちスイング動画から P1/P4/P7 が正しく切り出せる |
| **M2** | キーフレーム検出を P1〜P10 に拡張 + metrics 算出 | 10ポジションの静止画と角度 JSON が返る |
| **M3** | Dify アプリ結線（HTTP→Vision 診断→Answer）。ビュー自動判定込み | 動画アップ→テキスト診断が返る |
| **M4** | 注釈画像生成（弱点ポジション最大3枚） | 注釈画像付きの回答が返る |
| **M5** | Notion 記録 + 定点観測（過去レコード取得・前回比） | 2回目の分析で前回比コメントが出る |
| **M6** | ドリル知識の RAG 化（運用しながら随時） | `knowledge/swing-drills.md` をナレッジ登録し切替 |
