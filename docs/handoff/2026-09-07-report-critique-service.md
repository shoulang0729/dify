## 0. 目的 / 背景

### 0-1. 元ネタ（Notion 2 本。PM 執筆）の要点

**A. 報告ツッコミエージェント 指示書**（本体）

- 役割：週報・営業報告・案件報告・稼働報告・組織報告を読み、**経営者・責任者が意思決定できる水準まで論点を深掘り**する。責めない。曖昧さ・論理の飛躍・数字の不整合・実行計画の不足を、建設的な質問と改善案に変換する
- 原則 7：①原因説明と対策説明を分ける ②不足額と補填策を数字でつなぐ ③手段と目的を混同させない ④制約を所与にしない（増員・外注・再配置・優先順位・スコープ）⑤曖昧な主体を特定（氏名・組織・役割）⑥未確定を確定のように書かせない（事実・推測・予定・決定をラベル）⑦読み手が次に判断できる状態を作る
- 観点 A〜H：目標・差分／数字の整合性／事実と解釈／打ち手の具体性／制約と代替案／主体・責任／リスク・依存関係／報告表現（曖昧語・主語なし・結論不明）
- 深さ 5 段階：確認 → 差分 → 打ち手 → 代替案 → 経営判断
- 出力 6 部：①エグゼクティブサマリー ②良い点 ≤3 ③重要なツッコミ ≤5（論点・根拠・質問・期待する回答形式・放置リスク）④数字のブリッジ表 ⑤改善後の報告案（結論→差分→打ち手→リスク→依頼）⑥次回確認事項
- 生成ルール：結論先／重要度順／3〜5 件に絞る／回答形式を指定／人格でなく内容／皮肉・威圧なし／原文にない事実を作らない・推測は「推測」と付ける／単位が曖昧でも勝手に補正しない／同じ指摘の再発は未解決理由を問う
- 継続の仕組み：**指摘・回答台帳**（報告日・報告者・種別・論点分類・指摘・回答・約束・期限・ステータス・再発回数・有効だった知見）。次回報告で前回台帳と照合（未完了・期限超過・確度変化・同じ曖昧表現）。月次品質レビュー（解決率・再発率・期限内回答率。**個人攻撃に使わない**）
- 禁止：根拠なく断定／数字を都合よく補完／人格批判／皮肉・圧力／表記揺れの大量指摘／機密の必要以上の展開／未確定を決定として台帳保存

**B. 週報改善レビューAI：Dify 実装指示書**

- 週報作成規定（KB）と Excel/Word 週報を照合し、**行単位で `keep` / `improve` / `merge` / `remove` / `needs_review`**、件数集計は Code ノード、構造化 JSON → Markdown
- 日常事務（メール返信・会議参加のみ・週報作成）は削除候補。曖昧表現（「一部確認」「対応中」）には対象・完成度・残課題・期限の追記を求める。事実を創作しない。受入テスト 8 件

**A と B の関係（本設計の決定）**：DC-08 は **1 つの Workflow に直列**で組む。**第 1 段＝B（規定照合・行整理）→ 第 2 段＝A（論点ツッコミ）**。A が本体、B は前処理。詳細は `docs/dify/usecases/DC-08.md` §4。
