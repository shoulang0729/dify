### 9-3. 画像・PDF の作り方（`tools/gen-demo-assets.mjs`）

1. **SVG を JS で組み立てる**（帳票の罫線・欄名・刷り文字は通常のフォント、記入内容は「手書き風」）。
2. **手書き風は SVG の変形で作る**（手書きフォントは環境に無い）。1 文字ずつ `<text>` にして：
   - `rotate(-6°〜+6°)` のランダム回転、`dx/dy` を ±1.2px 揺らす
   - `font-size` を ±8% 揺らし、`stroke-width` も揺らす（筆圧のムラ）
   - `feGaussianBlur(stdDeviation 0.35)` を薄くかける（にじみ）
   - 数字の一部を**罫線からはみ出させる**
   - 訂正箇所は `<line>` の取り消し線＋上に書き直し
   - 日本語は `IPAGothic`、中国語は `WenQuanYi Zen Hei` を `font-family` に明示指定（環境に実在。`fc-list` で確認済み）
3. **紙の質感**：薄いベージュの背景＋微細なノイズ矩形、ページをわずかに回転、影を落とす。撮影感を出すため HTML 側のラッパで `transform: perspective(...) rotateX(1.5deg) rotateZ(-0.8deg)` を掛けてからスクリーンショットする。
4. **Chromium（Playwright）で JPEG 化**：`page.setContent(html)` → 対象要素の `screenshot({ type: 'jpeg', quality: 82 })`。`deviceScaleFactor: 2`、ビューポート固定。
5. **PDF は `page.pdf({ format: 'A4' })`**（Chromium のみの機能。作業標準書 2 版）。
6. **再現性**：乱数は `mulberry32` の**固定シード**（ファイルごとに固定値）。`Date.now()`・`Math.random()` を使わない。`--check` で再生成して**既存ファイルとバイト比較**し、違えば非ゼロ終了。
   > **ただし Chromium のバージョンが変わるとバイトは一致しなくなる。** したがって `--check` は **CI に入れない**。生成した本人が 2 回走らせて同一であることを確認し、使った Chromium のバージョンを `mock/assets/demo/README.md` に書く。reviewer は「生成物がコミットされている」「サイズ上限内」「verify §20 が PASS」までを見る。

**Playwright の解決の仕方（`dependencies` を足さない）**：

```
このツールは playwright をリポジトリの依存にしない（CLAUDE.md §2-14 18-b：ルート package.json の
dependencies はゼロのまま）。次の順に解決し、見つからなければ「グローバルに playwright を入れてから
実行してください」と出して exit 1 する。npm test / CI からは絶対に呼ばない。
  1) import('playwright')
  2) createRequire で `npm root -g` のパスから解決
```

（確認済み：この環境には `playwright 1.56.1` がグローバルに入っており、`NODE_PATH=$(npm root -g)` で Chromium が起動し PNG/JPEG を書けた。日本語フォント `IPAGothic`・中国語フォント `WenQuanYi Zen Hei` も実在する。）

### 9-4. 音声の作り方 —— **PM 判断（Q6）**

**この環境には TTS が無い。** 確認結果：`espeak` / `espeak-ng` / `ffmpeg` / `sox` / `lame` はいずれも**不在**。`python3` と `pip3` は動き、**PyPI へは到達する**（`gTTS` のダウンロードに成功）。

| 選択肢 | 中身 | 良い点 | 悪い点 |
|---|---|---|---|
| **① オンライン TTS**（`gTTS`／`edge-tts` 等） | 台本テキストを外部の読み上げサービスへ送り、返ってきた音声を WAV に変換 | 本物の読み上げ。ja/zh の差が出る。デモで再生して「音声です」と言える | **架空とはいえ台本テキストを外部サービスへ送る**。MP3 で返るものは WAV 変換に `ffmpeg` が要る（不在）。**PM の明示承認が要る** |
| **② オフライン合成（推奨・既定）** | 純 Node で WAV を書く。工場の環境音を模した帯域制限ノイズ＋発話のリズムを模した低いトーン列。**声は入らない**。同名の `.txt`（文字起こし）を必ず併置 | 外部に何も送らない。依存ゼロ。決定的（シード固定）。実機 P-1 にそのまま投げられる形式（16 kHz mono 16bit PCM） | 再生しても**言葉は聞こえない**。デモで再生ボタンを押すと期待とずれる |
| ③ PM が録音 | 実在の声 | 本物 | **実在の人の声＝個人情報。差し替えが効かない。採らない** |

**推奨：② を既定にする。** そのうえで：
- UI の注記（`T.upNote` / `PT.upNote`）とは別に、**音声チップの直下に 1 行**「デモ用の合成音です（声は入っていません）。文字起こしは `…-ja.txt` と同じ内容です」を出す（`T.upAudioNote` は作らず、`mock/assets/demo/README.md` と `docs/demo/runbook-showcase-mfg.md` §4 に司会の言い方として置く。**UI の文言キーを増やさない**）。
- **デモでは再生ボタンを押さない運用を推奨**（進行台本 §2 幕 2 に明記。押しても壊れないが、価値は「読み取り結果の返し方」にある）。
- **PM が ① を承認したら**、同じファイル名（`kn11-interview-ja.wav` / `-zh.wav`）を差し替えるだけでよい設計にする（台本・`assets` のパスは変えない）。その場合 `tools/gen-demo-assets.mjs` に `--voice` オプションを足し、**既定では走らない**ようにする。

**仕様（① ② 共通）**：16 kHz / モノラル / 16 bit PCM / WAV。長さ 10〜20 秒（**1 MB 以内**）。台本上の「32 分 14 秒」は**帳票上の設定値**であり、ダミーは抜粋であることを `README.md` と `.txt` の冒頭に書く。

## §10. アップロード操作の実装（PR-3）

### 10-1. 何ができるようになるか

`upload` テンプレートの入力パネルが、いまの「ファイル名のチップが並ぶだけ」から次になる。

```
 ┌──────────────────────────────────────────────┐
 │  ┌ ドロップゾーン（点線の枠） ──────────────┐ │
 │  │   ファイルをここにドラッグ、               │ │
 │  │   またはクリックして選択                   │ │   ← T.upDrop
 │  │   （クリックで <input type="file" multiple>）│ │
 │  └──────────────────────────────────────┘ │
 │  [ サンプルを使う ]  [ クリア ]                │   ← T.upSample / T.upClear
 │                                                │
 │  ┌ 載っているファイル ────────────────────┐ │
 │  │ 🖼 外観検査記録_手書き_L3_0905.jpg         │ │
 │  │    ┌────────────┐                        │ │
 │  │    │  プレビュー  │  ← <img> 120px 角     │ │
 │  │    └────────────┘                        │ │
 │  │ 🔊 聞き取り音声_…_2025-09-12.wav          │ │
 │  │    [▶ ──────────── 0:00 ] ← <audio controls>│ │
 │  │ 📄 段取り作業標準書_WS-L3-04_RevC.pdf  開く │ │
 │  └──────────────────────────────────────┘ │
 │                                                │
 │  ⓘ このモックは読み取りを行いません。…        │   ← T.upNote（3 言語）
 │                                                │
 │            [ 実行 ]   ← 既存の data-act="run"  │
 └──────────────────────────────────────────────┘
```

- **「サンプルを使う」**：`SCENARIOS[svc].input[lang].assets` のパスを**そのまま** `<img src>` / `<audio src>` / `<a href>` に入れる。`fetch()` は使わない。発表者はこのボタン 1 つで迷わない。
- **ドラッグ＆ドロップ / ファイル選択**：ユーザーが選んだファイルは、画像なら `FileReader.readAsDataURL`、音声なら `URL.createObjectURL` で表示する。**送らない・保存しない**（`localStorage` 禁止＝§2-6）。`URL.revokeObjectURL` をクリア時に呼ぶ。
- **「実行」**：**既存の `data-act="run"` の流れをそのまま使う**。ファイルが 0 件でも従来どおり動く（`assets` を持たない既存の upload 台本＝ DC-03・KN-05 などは**見た目も動きも変わらない**）。
- 実行後に出るのは**台本の 1 往復目**＝読み取り結果（読めた／読めなかった／確信度／人が直す 1 手）。

### 10-2. 置き場（共通ファイルを新設しない理由）

`portal.html` は `js/app.js`・`js/render.js` を**読んでいない**（verify §17-a が `<script src>` の本数と順序を実ディレクトリから計算して突き合わせている）。共通部品を `mock/js/upload.js` として新設すると、

- `catalog.html` と `portal.html` の `<script src>` の**並びが変わる**
- `CLAUDE.md` §2-3 が load-bearing として明記している読み込み順（`data/ui → data/catalog → data/home → data/style → data/scenarios/* → app → render → events`）が**古くなる**
- `tools/verify.mjs` の §17-a の期待値配列とカタログ側の順序検査を同時に直す必要がある

**この 3 つのコストを払う価値が無い**（部品は 60 行程度）。しかも**ポータルの台本ドロワーは元から `render.js` と別実装**（`mock/js/portal/demo.js` が独自に描いている）。既存のこの作りに合わせる。

| 何を | どこに |
|---|---|
| 載っているファイルの配列（表示用メタ。`{name, kind, src, objectUrl}`） | `mock/js/app.js` に**モジュールスコープの `let upFiles = []`**。**`state` には入れない**（`state` の必須キー一覧＝§2-3 の load-bearing を動かさないため。言語切替の再描画では `upFiles` がそのまま残るので、会話と同じく復元される） |
| 入力パネルの描画 | `mock/js/render.js` の `upload` 分岐 |
| クリック（サンプル／クリア）・`change`・`dragover`/`drop` | `mock/js/events.js` |
| 同じもののポータル側 | `mock/js/portal/demo.js`（描画・`let pupFiles = []`）と `mock/js/portal/events.js`（操作） |
| 見た目 | `mock/css/components.css`（カタログ）・`mock/css/portal.css`（ポータル）。**`#RRGGBB` の直値を書かない。`var(--surface-*|--text-*|--border-*|--action-*)` だけ**（§2-2） |
| 文言 | `mock/js/data/ui.js` の `T` に 4 キー（§10-4）／`mock/js/data/portal/ui.js` の `PT` に同じ 4 キー |

### 10-3. `data-act` を増やさない

`CLAUDE.md` §2-3 は `data-act` の値の一覧を load-bearing として列挙しており、verify もそれを検査している。**アップロードの操作は `data-act` を使わず、`data-up`（カタログ）／`data-pup`（ポータル）で受ける。**

| 属性 | 値 | 動き |
|---|---|---|
| `data-up` / `data-pup` | `sample` | `assets` を載せる |
| 同上 | `clear` | 全部外す（`revokeObjectURL` も） |
| 同上 | `pick` | 隠した `<input type="file">` を `click()` |

（前例：ポータルは既に `data-know="new"`・`data-pact` のように `data-act` 以外の属性を使っている。）

### 19-17. verify §20-f の誤検出と恒久修正（コメントを検査対象から外す）
