## 1. 目的と既存構造

セミナーで手書きの紙を大きく見せ、記入内容・曖昧な数字・記録の食い違いを参加者と確認できるようにする。

現状は `upFiles` に載った画像を `upItemHTML()` が120px四方・`object-fit: cover`で表示する。`upUseSample()`は台本の既存相対パスを、`upAddFiles()`は手元の画像のDataURLを同じ `upFiles` に載せる。本変更もこの配列を表示の正本とする。QA-01のパスを新たにハードコードしない。

QA-01の対象は外観検査記録9/5・9/6、塗装条件記録9/5の3画像。画像上の線や重ね書きはそのまま残す。候補値（3.8／3.6、12／17）と人の確認後の確定値は既存台本の記録であり、拡大表示によって原画像を書き換えたり、自動確定したりしない。

## 2. UIと最小操作

画像サムネイルをネイティブの `button type="button"` にし、Enter／Space／クリックでモーダルを開く。名前とサムネイルを同じ操作領域に置き、開くボタンのアクセシブル名にはファイル名を含める。サムネイル自体も `object-fit: contain` へ変更し、紙の全体を示す。画像以外の音声・文書は既存の表示と操作を保つ。

```text
┌ 画像プレビュー ─────────────────────── [閉じる] ┐
│ 選択中のファイル名                           1 / 3 │
│ [前の画像] [次の画像]  [−] [全体表示] [＋] 100% │
├───────────────────────────────────────────────┤
│                                               │
│          原票全体（初期）／拡大した原票          │
│          拡大時は縦横スクロールで移動            │
│                                               │
├───────────────────────────────────────────────┤
│ 既存の T.upNote                                │
└───────────────────────────────────────────────┘
```

- `dialog.showModal()` を使い、背景を操作できないモーダルとして `document.body` に1つだけ配置する。タイトルを `aria-labelledby` で結び、画像の代替テキストはファイル名にする。説明には既存 `T.upNote` をそのまま再利用する。
- 画面の幅・高さから各16pxを除いた領域を使う。高さは `100vh` をフォールバックとして `100dvh` に対応。外枠は固定高さ、画像表示領域だけが縦横スクロールする。ヘッダー／ツールバー／注記は画像と一緒に流さない。
- 初期は元の縦横比を保って原票全体を画像表示領域に収める。クロップ・回転・画像再生成・補正はしない。表示画像の `src` は選択中の `upFiles[i].src` をそのまま使う。
- 拡大率は全体表示を100%として100／150／200／300／400%。拡大・縮小はこの段階を移動し、端では対応ボタンを無効化。「全体表示」は100%とスクロール位置をリセットする。元画像の100%ピクセル表示とは区別する。
- 拡大した寸法を実際の画像レイアウト幅・高さへ適用し、画像の四隅までスクロールできるようにする。CSS transformだけで拡大してスクロール可能領域が増えない実装は避ける。画像切替後・リサイズ後は全体表示へ戻す。
- 前後の切替対象は `upFiles` の `kind === 'image'` のみ。配列順を保持し、端は無効化して循環させない。1枚の場合は前後ボタンを出さない。ファイル名と `{current} / {total}` は選択中画像と一致させる。
- 閉じるボタンとEscで閉じる。開くときは閉じるボタンへフォーカスし、Tab／Shift+Tabをモーダル内に留める。閉じたら起点のサムネイルボタンへ `preventScroll` 付きでフォーカスを戻す。背景スクロールも元の状態へ戻す。
- モーダルの外側クリックでは閉じない。画像切替・拡大縮小でモーダル全体を作り直さず、押したコントロールのフォーカスを保つ。
- 画像読み込み失敗時はエラー文言を表示し、閉じる・別画像への切替を残す。ファイル名が長い場合も折り返してコントロールを押し出さない。

## 3. 状態・イベント・寿命

`state`とは別に、app.jsのメモリ内に表示中か・選択したupFilesのindex・拡大率・起点要素・背景スクロールの復帰情報を持つ。`upFiles`の形は変えず、viewerが別の配列へファイルをコピーして保管しない。

```text
閉じている → 画像ボタンを押す → 選択画像を全体表示
全体表示／拡大表示 → ＋／−／全体表示 → 表示寸法と倍率を更新
表示中 → 前／次 → 対象画像を全体表示（先頭・末尾で停止）
表示中 → 閉じる／Esc → 終了・背景復帰・起点にフォーカス
表示中 → upClear／サービス離脱 → 終了・背景復帰（消える起点へ戻さない）
```

操作は既存アップロード系と同じ `data-up` を使い、`preview`／`preview-close`／`preview-prev`／`preview-next`／`preview-zoom-in`／`preview-zoom-out`／`preview-fit` を追加する。画像ボタンには数値のupFiles indexを渡し、操作時にも配列範囲とkindを検査する。`data-act`は追加しない。

開く・拡大・切替・閉じるだけで `renderMain()`／`renderAll()`／`consume()`を呼ばず、`state.log`・入力値・台本進行を保つ。通常の再描画が起きてもbody上のモーダルは維持し、起点が再生成された場合は同じupFiles indexの画像ボタンへ戻す。起点が存在しない場合は、現画面の入力パネル内の既存ボタンへ戻す。サービス離脱時は閉じる。クリアはモーダルを先に閉じ、既存のURL破棄を行う。

UI表示以外の処理は追加しない。読み取り・OCR・AI呼び出し・ファイル送信・保存・外部サービスとの連携はない。既存の相対パス／DataURLで表示し、fetchや外部依存を追加しない。

### 8-1. 対象と表示方法

製造業 `mfg`・サービス `qa1`・demo画面の既存台本の**assistant回答だけ**を対象とする。ユーザー入力、挨拶、台本終了後の汎用回答、結果パネル、他サービス、ポータルには適用しない。

`mock/js/data/scenarios/mfg/qa.js` の **qa1にだけ**任意の `highlights: { ja: [...], zh: [...] }` を追加する。下表の引用を言語別の共通配列にし、ターンごとの別台本文や新しい文章は作らない。短い完全一致引用で、同じ引用が該当回答内に複数あれば全てに印を付ける。原因順位・最有力という語句には印を付けない。

| 意図 | jaの完全一致引用 | zhの完全一致引用 |
