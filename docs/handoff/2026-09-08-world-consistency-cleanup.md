## 5. 判断点：(c) の置き場をどこにするか

**「文書番号の体系」表は“書式”の表であり、規程・マニュアルは“台帳”である。** この 2 つは検査の仕方が根本的に違う。

- 文書番号は **書式に合っているか**で判定する（`NC-2026-0619` は台帳に無くても正しい）
- 規程 ID は **台帳にあるか**で判定すべき（`RULE-99` は書式に合っていても存在しない）

`calendar.md` に `RULE-NN` という**書式**を足すと、`RULE-99` のような存在しない規程が通ってしまう。これが「体系の意味が壊れる」の実体である。

### 5-1. 比較した 3 案

| 案 | 中身 | 良い点 | 悪い点 |
|---|---|---|---|
| **A** | `calendar.md` に 2 つ目の見出し「## 規程・マニュアル番号」を足す | ファイルが増えない。W6 のパーサは `## 文書番号の体系` 配下しか読まないので混ざらない | 「カレンダー・文書番号体系」のファイルに**行が増え続ける台帳**が同居する。3 言語のタイトル・所管部署・版を持つと md の表が破綻する。**書式か台帳かの区別が読み手に伝わらない** |
| **B（採用）** | **`data/world/<業種>/documents.csv` を新設** | 台帳は CSV が自然（`products.csv`・`equipment.csv` と同じ位置づけ）。3 言語タイトル・所管・版を列で持てる。KB 文書（`dify/kb/**` のヘッダ「文書番号」）と 1:1 で紐づく。**検査が「書式一致」ではなく「台帳に実在するか」になる**。顧客版で実物の規程台帳に差し替える単位としても分かりやすい | `data/world/` のファイルが 1 つ増える（README の一覧に 1 行） |
| **C** | 正本に登録せず、W6 の除外接頭辞に列挙するだけ | いちばん安い | §2-13「新しい名前・数字はまずマスタに足す」に正面から反する。除外リストがまた `tools/` にハードコードされ、Issue #133 で潰したはずの“正本がツールの中にある”状態に戻る |

**決定：B。** 理由は上表の「検査が台帳照合になる」が決定的。加えて c2（社内システムのレコード ID・コード）も同じ「実在するかを台帳で見る」性質なので、`kind` 列で 1 ファイルに同居させる。

### 5-2. `documents.csv` のスキーマ

```
doc_id,kind,title_ja,title_zh,title_en,owner_dept,rev,note
```

- `doc_id`：正本の ID。**改名しない**（`SVCS[].id` と同じ扱い。不要になったら欠番）
- `kind`：`rule`（規程・マニュアル・様式台帳）／`record_id`（社内システムのレコード ID・匿名化 ID）／`code`（システムのエラーコード・区分コード）
- `owner_dept`：`org.csv` の `dept_id`（無い場合は空）
- `rev`：版・改訂日（無ければ空）
- `note`：出典（台本 / KB / 実装リファレンスのパス）

W6 は「候補コードが `documents.csv` の `doc_id` に**実在**すれば OK」と判定する（書式の正規表現は増やさない）。

### 5-3. あわせて直す誤分類：`QS-3310` は品番ではない

現在 `tools/check-world.mjs` は W6 の除外接頭辞を `(SK|PX|DO|ASSY|QS|J)` と**ハードコード**しており、`QS-3310` を「品番だから W6 の対象外」としつつ、W7 では「`products.csv` に無いコード」として warn している。
実体は**検査基準書**（`docs/dify/usecases/EN-01.md` の JSON では `doc_no`）である。

- W6 の品番接頭辞は**ハードコードをやめ、`products.csv` の `part_no` と `equipment.csv` の `equip_id` の先頭セグメントから組み立てる**（→ `SK` `ASSY` `PX` `D` `J` `DO`、`HT` を登録すれば自動で加わる）
- W7 の候補正規表現から **`QS` を外す**（`QS-3310`・`QS-xxxx` は品番ではない）
- `QS-NNNN` を `calendar.md` に文書番号として登録する（§4-1）

これにより W7 の warn は 7 → 5 になる（残るのは `SK-2207` `SK-2207-A` `J-2207` `PX-350` `PX-100`。品番マスタの拡充は本 Issue の対象外＝§8）。

## 7. `tools/check-world.mjs` の 2 つの穴

### 7-1. 穴 1：集計のキャップ（表示だけでなく合計も 10 件で止まる）

現状（W6）：

```js
if (!knownPatterns.some(re => re.test(c))) { unknown++; if (unknown <= 10) report(`…: ${c}`); }
if (unknown > 10) console.log(`   ほか ${unknown - 10} 件`);
```

`report()` の中で `warnCounts[currentInd]++` しているため、**11 件目以降は合計にも入らない**。W7 も同じ形（`if (n <= 15) report(...)`）で、いまは 7 件なので表面化していないだけ。

**直し方：件数の集計と、1 行ずつの表示を分ける。**

```js
// 集計は全件、表示は先頭 showMax 件。--all で全件表示
function reportMany(label, items, showMax = 10) {
  warnCounts[currentInd] += items.length;             // ← 全件を数える
  console.log('⚠️ ', `${label} ${items.length} 件`);
  const shown = showAll ? items : items.slice(0, showMax);
  for (const it of shown) console.log('    -', it);
  if (items.length > shown.length) {
    console.log(`    … ほか ${items.length - shown.length} 件（全件は --all）`);
  }
}
```

- W6・W7 の per-item `report()` を `reportMany()` に置き換える
- **`--all` フラグを新設**（`process.argv.includes('--all')`）。設計・レビューのたびにツールを書き換えて全件を見る、という現状の手間を無くす
- W1・W9 のように「1 行に集約して件数を本文に書く」検査は今回変えない（既に集計と表示が一致している）
- **この修正は判定結果を変えない**。表示される合計だけが `34 → 72` になる。README にその旨を書く（§3）

### 7-2. 穴 2：管理番号形式の除外が、登録済み書式より先に効く

現状の判定順（W6 のループ内）：

```
① 数字を含まない → skip
② ^[A-Z]{2}-\d{2}$（管理番号）→ skip     ← ここで CM-01 / QC-11 / QC-27 / QC-31 が消える
③ 品番接頭辞（SK|PX|DO|ASSY|QS|J）→ skip
④ 単独英字で calendar 未登録 → skip
⑤ knownPatterns に一致しなければ warn
```

`calendar.md` に登録済みの `CM-NN`・`QC-NN` は ② で先に落ちるため、**⑤ に到達しない＝実質デッドコード**（実測：`CM-01` `QC-11` `QC-27` `QC-31` の 4 種）。

**直し方：正本に登録されたものを最優先で「OK」と判定してから、除外に進む。**

```
① 数字を含まない                                → 対象外
② calendar.md の書式に一致                      → OK（正本が明示的に登録した書式が最優先）
③ documents.csv の doc_id に実在                → OK（規程・社内 ID の台帳。§5）
④ 管理番号形式 ^[A-Z]{2}-\d{1,2}$               → 対象外（§2-11 の管理番号／同形の運用ラベル）
⑤ 品番接頭辞（products.csv / equipment.csv 由来）→ 対象外（W7 の管轄）
⑥ 単独英字で calendar 未登録                    → 対象外（金型・アラーム・様式の別体系）
⑦ それ以外                                      → warn
```

**衝突したときの優先順位：`calendar.md` の登録済み書式が勝つ。** 正本が「これは文書番号である」と明示的に宣言しているものを、ツール側の一般則で黙って消してはいけない。

ただしこの優先順位には副作用があるので、**歯止めを 1 つ足す**（新検査。W6 の中で行う）：

> `calendar.md` に `^[A-Z]{2}-NN$` 形（2 文字接頭 ＋ 2 桁）の書式を登録するとき、その 2 文字が
> **`CATS[].id` を大文字化した分類コード**（§2-11 の管理番号の接頭辞）と一致してはならない。一致したら warn する。

現在の分類コードは `KN RS CV FA QA DC LG NM EN GN PT PO EG` の 13 個。登録済みの `CM` `QC` はどれとも衝突しないので、この検査は**現状 PASS**する。将来 `QA-NN` のような書式を足そうとした瞬間に止まる。

④ の `\d{2}` → `\d{1,2}` への緩和は、`docs/handoff/2026-09-06-pm-decisions.md` §6 を参照する **PM 決定ラベル `PT-3` / `PT-8`**（実装リファレンス中に出る）を拾わないため（§4-3 c3）。コメントでその理由を書く。
