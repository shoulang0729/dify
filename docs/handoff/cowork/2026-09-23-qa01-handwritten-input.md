## 2. 実務では誰が確定するか（2 往復目の入り方）

- 原票の読み直しは **記入者本人** が最も確実（書き損じか訂正かは本人にしか分からない）。塗装条件記録＝生産技術課（記入者 王磊）、外観検査記録＝検査員（9/5 陈静・9/6 周敏）
- **品質保証課（8D の起案者）は確定の依頼と記録**。確定値を 8D に載せ、確定の記録（元候補・確定値・確認者・日時）を残す
- 製造課は「読み取りの確定」ではなく **D3（暫定処置の実施）と D5（是正の実施）** で出てくる
- 変更後の 2 往復目の q は「王主任に原票を見てもらいました。…線は記入時の書き損じだそうです」。**顧客に「AI が迷った所だけ、書いた本人に聞く」と一言で言える**

## 3. docs/demo/faq.md Q32 を強くする材料（**本文は書き換えていない**。GN-02 の T09 が PASS するまで変えない＝`2026-09-21-gn02-ocr-input.md` §8）

いまの Q32 は「想定しています／確認できていません」の誠実さはあるが、**「読めなかったらどうするのか」への答えが無い**。確認状況と関係なく言える「返し方の約束」を 1 段落足す案：

> 読み取りを使う場合でも、**読めなかった所を推測で埋めることはしません**。読み取った結果は「読めた／読めなかった／自信がない」の 3 つに分けてお返しし、読めなかった所は空欄のまま、自信がない所は候補を並べて、原票のどこかを示します。空欄や候補のままの値は、報告書の判断の根拠にしません。確定するのは記録を書いたご本人で、確定した記録（元の候補・確定した値・確認した人）も残します。これは、読み取りの誤りが「一見正しく見える値」として紛れ込むのがいちばん危ないためです。

- 裏づけとして口頭で言える例（顧客資料には実名を書かない）：「スキャナが数字を別の数字に置き換えた有名な事例があり、見た目では気づけなかった」［13］／「最近の AI の読み取りは、読めない所をもっともらしい値で埋めてしまう傾向が報告されている」［14］［15］
- **やらないほうがよいこと**：精度の数字（「手書き 80%」等）を出す。こちらで測っていないため
