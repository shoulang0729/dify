## 1. 比べてわかったこと

### DC-03（音声・動画から教材・手順書）
- 世間の製品は「口頭の説明を文字起こし → 手順に分けて**ドラフト**」［1］［4］、字幕・翻訳・読み上げ［2］、基幹系の品目マスタからトルク基準を自動で紐づけ、**班長・技術者が審査して確定**［3］。専門用語の誤認識は前提で、用語辞書やカスタムモデルで補う［5］。AI が書いた製造文書を十分に見直さずに使い、当局から指摘を受けた例もある［6］
- **人が直すところ**は各社ほぼ共通：安全上の注意・数値（トルク等）・手順の順番・用語・写真。→ 台本に「人が確認するところ」として入れた
- **台本の問題**：`desc` の最終文「文書として残っていないベテランの手順や勘所は、聞き取りの音声を取り込んで教材と手順書のドラフトに起こすことを想定」が、**KN-11（聞き取り → 構造化 → 本人確認 → ナレッジ／標準へ）とほぼ同じ**になっている。KN-11 ができたいま、DC-03 が直接音声から教材を作ると「本人確認も標準との突き合わせも経ていない発言が、新人の教材になる」＝ KN-11 で見せた「見極め」と逆の流れになる
  → **推奨**：DC-03 は「承認済みの標準と、本人確認の済んだ技術メモ（KN-11 の出口）から教材を作る」に役割を寄せる。`desc` の最終文を差し替える案（Cowork では触らない。3 言語同時で）：
  > 文書として残っていないベテランの手順や勘所は、聞き取りから記録化するサービス（KN-11）で本人の確認を経た技術メモを取り込んで、教材に反映します。

### EN-03（類似図面検索・朱書き）
- 形状による類似検索は**製品として実用段階**。文字（品名・品番）だけでは「名前が似ていて形が違う」部品を探しきれず、形状＋図面内の文字の検索を併用［7］［8］。研究でも寸法・公差・表題欄を別々に読み取って組み合わせる試作がある［11］
- 手書きの読み取りは「可能」とうたう製品はあるが、**公開されている目安は手書き帳票で 80% 程度、100% は理論上困難で人の確認が要る**［9］。**線や記号に重なる図面上の朱書きの精度を示した公開データは見つからなかった**
- → EN-03 は構想（st3）のままでよい。台本で「朱書きを読める」と言い切らず、「読めた 1／読めなかった 1（埋めない）」の QA-01 と同じ返し方にした

## 4. docs/demo/faq.md Q31 の補強材料（**本文は書き換えていない**）

いまの答え（図面には書き込まない。「何ページの・どの欄の・どの記載」と言葉で示す。赤入れは既存の CAD・図面管理で）は、**世間の代替手段と合っている**。AI の図面チェックの研究・製品も、指摘を「報告書」「座標つきの一覧」「別の画面での重ね表示」の 3 つで返し［12］、指摘を課題として一覧・追跡する［13］。建築の図面審査でも、指摘の位置とスクリーンショットを報告書に載せ、クリックで図面の該当位置へ飛ぶ形がある［14］。

足すとよい 3 点（案）：
1. **位置の言い方を具体的に**：「何ページ・どの欄」に加えて「図枠の区域（例：C-4）」「指摘番号」を付けた一覧で返す。お客様が CAD・PDF の注釈で**番号を図面に付ければ、一覧と図面が対応する**
2. **正直な注意書き**：「位置は目安で、ずれることがあります。書かれていない注記を指摘してしまうこともあるため、採否は人が判断します」（位置のずれと存在しない指摘は研究でも限界として挙がっている［12］）
3. **手書きの朱書きについて**：「読めた朱書きは内容を一覧に入れ、読めなかった朱書きは推測で埋めず、場所だけを示して確認事項に回します」（EN-03 の台本と同じ返し方）

- 「座標つきの一覧を別の画面で重ねて表示する」は技術的には既存の手段があるが、**動作確認をしていないので、できるとは言わない**（Q31 の現行の線引きを維持）
