# GN-02：カタログと直接リンクのデモ入口を統一

## 再現・原因

公開版で集金予定表の直接リンクを開き、「詳細へ戻る」→「デモを見る」と操作すると、依頼文・既知のサンプル2件が消え、発票・発注・入庫の候補が再び表示された。直接リンクの起動だけが `gn2PrepareCollectionDemo()` を呼び、通常の `start` 遷移には同じ準備処理がなかった。

## 変更・受け入れ条件

製造業GN-02の `start` 遷移でも、既存の集金予定表準備処理を使用する。カタログからの初回開始と詳細からの再開、直接リンク、最初からの操作で、依頼文と「請求データ_サンプル.xlsx」「集金予定表_完成見本.xlsx」の2件が揃い、候補は集金予定表の1件。自動送信せず、送信1回で初稿、続く日付確認・修正で修正版とExcel出力。送信済みの添付欄は閉じる。

他サービスの開始、言語・テーマ・お気に入りの保存、任意ファイルの未解析ガードは維持。台本・Excel・スライド・データ件数・Dify実装には変更なし。旧買掛台本は変更せず、チャットで依頼した場合の処理は従来通り。

## 検証

JA/ZH/ENのカタログ開始・詳細からの再開・再開始、送信1回で初稿、添付移動・消去、QA-01/NM-05等の開始分離の実行検証に合格。既存のGN-02修正後Excel・入力ガード・チャット・直接リンク検証も合格。`npm run ci` 合格（Dify dry-run 49/49）。差分監査は起動処理1行のみ。ローカル実画面で詳細からの再開・送信1回の初稿・添付欄が閉じることを確認。マージ後にGitHub Pagesでも同じ操作を確認する。
